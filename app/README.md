# Application code

Chapter 28 checkpoint, 17 November 2026; complete chapter draft for review.
This folder is the continuous project source: the Django 6.1.2 project
configuration, manage.py, the environment-check helper, installed
accounts, events, and registrations apps, the uv project files (pyproject.toml and uv.lock), and the npm
files for the stylesheet build (package.json, package-lock.json, and
.node-version). Settings read DJANGO_SECRET_KEY (required), DJANGO_DEBUG,
DJANGO_ALLOWED_HOSTS, and DJANGO_ADMIN_URL (the admin site's path, default admin/)
through python-decouple: environment variables
first, then a local .env.
Every page extends templates/base.html, found through TEMPLATES DIRS, which
includes templates/includes/site_nav.html and links static/otahque/site.css
through STATICFILES_DIRS and the static tag. site.css is generated by
Tailwind CSS 4.3.4 and daisyUI 5.7.50 from static/otahque/source.css (the
proposed otahque light theme, base rules, and two Otahque component
rules) and the class names in the templates; it is committed, so Django
runs without Node.js. Home renders a template; since Chapter 19 the event
list and detail pages read published events from the database (the list
row is an inline partial; the detail shows the start and end times in the
event's own time zone), and drafts, cancelled events, and unknown ids return 404.
events/models.py holds the proposed Event model from Chapter 16 (title,
starts_at, ends_at, timezone, location, capacity, and a TextChoices status
defaulting to draft; ordered by starts_at). accounts/models.py holds the proposed custom user from Chapter
17: accounts.User (AbstractBaseUser with PermissionsMixin) signs in with a
unique email, has a required display_name, and is created through
accounts/managers.py's UserManager; settings set AUTH_USER_MODEL =
'accounts.User'. Five tests check the configured model,
password hashing, required fields, and the manager's two refusals, without
a database. docs/adr/ holds ADR-001 and ADR-002 (both Proposed).
Chapter 18 adds the first migrations, kept as makemigrations wrote them:
accounts/migrations/0001_initial.py (the user, depending on auth 0012) and
events/migrations/0001_initial.py. Three TestCase tests save users and
check the unique email in the database, and config/tests.py fails if a
model change has no migration (29 tests). Chapter 19 moves the page tests
to TestCase with setUpTestData: the list shows published events soonest
first in one query, the detail shows the local time and location, drafts
and cancelled events are hidden, and titles are escaped (30 tests; the
Chapter 12 sample_label filter and its tests were removed). Chapter 20 adds the
registrations app (Registration: event and member foreign keys, status, registered_at,
cancelled_at) and events.OrganizerAssignment (event and member, assigned_at,
revoked_at); every foreign key uses PROTECT and an explicit related_name, migrations
events/0002_organizerassignment.py and registrations/0001_initial.py; public pages are
unchanged (36 tests). Chapter 21 adds database constraints: one active registration
and one current organizer assignment per member and event (partial unique indexes),
cancelled_at filled exactly when a registration is cancelled, capacity above 0, an
event ending after it starts, cancellations and revocations in time order, and each status from its list (CHECK constraints); a time-zone validator on Event; and
lower-case email addresses (the manager, User.clean(), and a CHECK constraint), in
migrations events/0003_rules.py, registrations/0002_rules.py, and
accounts/0002_email_lowercase.py (51 tests). Chapter 22 adds named
QuerySet methods with no migration: EventQuerySet.published(), used by both public
views, upcoming(now) and past(now), and RegistrationQuerySet.active(), attached as each
model's objects manager; the list page shows upcoming events first and past events
after them, faded; with_places() annotates places left, shown on both pages for events
still to come (58 tests). Chapter 23 configures the admin site for the community
administrator, with no migration: event, organizer-assignment, registration (view only),
and user (no password) admins, a read-only registrations inline, a read-only audit log
of LogEntry rows, OrganizerAssignment.validate_constraints() so the admin's forms show
Chapter 21's messages, and docs/design/admin.md (77 tests). Chapter 24 adds the first form,
with no migration: events/forms.py's EventForm (a ModelForm with an explicit fields list, no
status; times read in the event's own zone by in_zone() and clean(), clock-change times
refused), the New event page at events/new/ (login_required and permission_required for
events.add_event; LOGIN_URL is the admin's sign-in until Chapter 27; Post/Redirect/Get with
a message), Event.add_organizer() and Event.is_visible_to() (drafts and cancelled events
shown to current organizers and view_event holders only), a messages block in base.html and a
New event link for add_event holders, config/renderers.py (TemplatesSetting) with
templates/forms/field.html and widget templates under templates/django/forms/widgets/, theme
error and success colours, static/otahque/event-zone.js, and docs/design/event-draft-form.md
(97 tests). Chapter 25 adds the Edit event page, with no migration: events/<id>/edit/ (named
events:edit) for current organizers who hold events.change_event (Event.has_organizer() and
can_be_edited_by(); 404 when the event is hidden, 403 when refused); EventForm with an instance
showing saved times in the event's zone (with a line of both readings), keeping untouched times,
and asking for a tick box before a new zone moves the event; clean_capacity() and
Event.clean() (capacity never below the active registrations, in the page and the admin;
CAPACITY_MESSAGE shared with the constraint); a places-taken notice; an Edit event link;
templates/django/forms/widgets/checkbox.html; wrapping help in templates/forms/field.html; and
the design note extended (124 tests). Chapter 26 adds publishing, cancelling, and deleting: Event.description
(events/0004_event_description, blank for a draft), get_absolute_url(), readiness_problems(), publish(),
cancel(), delete_draft() and copy_as_draft(); the organized_by() query; the My events page at
events/manage/; POST-only publish and cancel views, a delete page that confirms on GET and deletes on
POST, and a copy page; cancelled events show a Cancelled tag and leave the lists; a textarea widget
template; error messages styled; and docs/design/event-states.md (165 tests). Chapter 27 adds member accounts with django-allauth 65.22.1
(ADR-003): sign-up asking a display name and an optional time zone (accounts/forms.py), refusing
disposable addresses with disposable-email-domains (accounts/adapter.py), sign-in by email in any case,
sign-out by POST, Google and GitHub from .env, no linking by email alone; accounts.Profile
(accounts/0003_profile) and the profile page at accounts/profile/; LOGIN_URL = account_login;
allauth templates in Otahque style under templates/allauth/; "Organized by" on event pages; and
docs/design/sign-in.md (190 tests). Chapter 28 adds no package and no migration: the event list
remembers "Only events with places left" in the session (saved only when changed; cleared at sign-out);
messages explained, with a close button in static/otahque/site.js; site.js also writes the browser's
zone to the otahque_tz cookie; accounts/timezones.py (resolve_timezone: profile, then a real-zone cookie,
then UTC; to_user_time) and accounts/middleware.py (TimezoneMiddleware after AuthenticationMiddleware,
skipping the admin, which stays in UTC); EventForm and CopyForm clean under UTC (UtcCleaning);
Event.differs_for() and events/templates/events/when.html show the venue's time and the viewer's; and
docs/design/sessions-and-time-zones.md (224 tests). Running migrate creates the
tables in each reader's own db.sqlite3, which Git ignores; this folder
holds no database, saved users or events, or public server. docs/design/erd.md holds
the proposed first-release data model from Chapter 15 (status Proposed;
no table exists yet).

The same code is kept in the pydata-otahque/ Git repository, where each
change goes through a reviewed pull request before it is copied here.

Follow the chapter before running commands. Use uv 0.13.5, Python 3.14.9,
and the locked Django 6.1.2 and python-decouple 3.8; for the stylesheet
build, Node.js 26.13.0 with npm 11.20.0. Work on a copy in your own folder:
create the environment with `uv sync --locked`, then create your own .env
with the key generation command in Chapter 8, Step 3 (.env.example lists
the names). Install the build tools with `npm ci` and rebuild with
`npm run build`. Never copy .venv/, node_modules/, or another computer's
.env. Run Django commands as `uv run python manage.py ...`; the settings
find .env beside manage.py. Never edit site.css by hand.

This folder holds no .env and no Git repository; readers create both in
Chapter 8. Apply the committed migrations with migrate; never edit them by
hand, and commit each model change with its migration. Use loopback HTTP only and stop runserver after use.
