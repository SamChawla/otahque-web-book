# M2 acceptance trace: the first release

Each rule from Chapter 2 (Table 2.3), the cases that prove
it, and the tests that check each case. Names are
`Class.test_name`; the app is given in brackets.
`TraceTests` (config) fails if a named test is missing.

Evidence: `check.py` passes locally and in CI on the commit
tagged v0.1.0, with the suite also run in reverse order.
The release checklist is docs/release-checklist.md.

## PR-1 One confirmed registration

Allowed:
- An eligible member gets one place (registrations):
  `RegisterTests.test_a_place_is_made`,
  `RegisterPageTests.test_a_member_registers_with_one_post`
- The member and the organizer see it (registrations):
  `MyRegistrationsTests.test_the_page_lists_upcoming_places`,
  `AttendeeListTests.test_the_list_shows_contacts_and_counts`

Refused, and nothing saved:
- A repeated request keeps one place (registrations):
  `RegisterTests.test_a_second_request_keeps_one_place`,
  `RegisterPageTests.test_two_posts_make_one_place`,
  `RaceTests.test_the_same_member_twice_gets_one_place`
- Full, closed, or not published (registrations):
  `RegistrationRuleTests.test_a_full_event_says_so`,
  `RegistrationRuleTests.test_closing_is_exclusive`,
  `RegistrationRuleTests.test_a_past_event_is_closed`,
  `RegistrationRuleTests.test_only_published_events_take_places`,
  `RegisterTests.test_a_refusal_names_why_and_saves_nothing`
- Signed out, or the email not confirmed (registrations):
  `RegisterPageTests.test_a_visitor_signs_in_and_comes_back`,
  `RegistrationRuleTests.test_an_unconfirmed_email_is_named`

## PR-2 Cancellation releases one place

Allowed:
- The first cancel releases one place (registrations):
  `CancelTests.test_cancel_releases_the_place_once`,
  `MyRegistrationsTests.test_confirm_then_cancel`
- A late cancel is allowed and marked (registrations):
  `CancelTests.test_late_from_the_deadline`,
  `MyRegistrationsTests.test_a_late_cancel_is_marked`
- The member may register again (registrations):
  `CancelTests.test_a_member_may_register_again`

Refused, or changes nothing:
- A repeat, or a lost response sent again (registrations):
  `CancelTests.test_a_stale_copy_changes_nothing`,
  `MyRegistrationsTests.test_a_repeated_cancel_is_information`
- After the start (registrations):
  `CancelTests.test_no_cancel_once_the_event_starts`,
  `MyRegistrationsTests.test_the_page_refuses_after_the_start`

- A cancel overlaps a request (registrations):

  `RaceTests.test_busy_while_another_request_holds_it`,
  `BusyEditTests.test_a_busy_edit_says_so_and_saves_nothing`

## PR-4 Own records, assigned events

Allowed:
- An organizer edits an assigned event (events):
  `EditAccessTests.test_organizer_gets_the_form`
- The attendee list for its organizers (registrations):
  `AttendeeMatrixTests.test_every_row`

  `CsrfTests.test_a_post_without_the_token_is_refused`,
  `EditCsrfTests.test_an_edit_without_the_token_is_refused`,
  `ActionCsrfTests.test_publish_needs_the_token`
- Refusals are recorded (events):
  `AuditTrailTests.test_refusals_by_members_are_recorded`

## PR-5 Publication boundary

Deferred: no workload or target is agreed yet. Chapter 66

## Known limits

- A cancel saved while another request counts can refuse
  that request although a place is free a moment later
  (PR-3, the overlap test). It never gives a place too
  many. The member can press Register again.
- Not in M2, so not tested here: email notices, the
  waitlist, check-in, and reminders (M3).
- The UI checklist is a first check, not an accessibility
  certification.
