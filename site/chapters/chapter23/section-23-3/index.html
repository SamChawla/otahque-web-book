How We Build It

Start from Chapter 22, in the folder containing manage.py, with your own .env, the locked environment, 58 passing tests, every migration applied, and the rows Chapter 22 left: four events, two of them published; Sam, Sai, and Raj; Sai’s two active registrations and Raj’s cancelled one; Sam’s organizer assignment for the Python meetup; and Sam’s superuser password, which you chose in Chapter 18. Step 2 signs in and moves the admin’s address into settings, in config/settings.py, config/urls.py, .env.example, and your .env. Step 3 writes the access tests in config/tests.py. Steps 4 to 7 each write a model’s tests first and then its admin class: events and the registrations shown under them in events/admin.py, registrations in registrations/admin.py, organizer assignments back in events/admin.py with one method added to events/models.py, users in accounts/admin.py, and the audit log in the same file. Step 8 writes docs/design/admin.md, and Step 9 commits. At the end, 77 tests pass, the admin site lists Otahque’s four models and the audit log with the limits of Figure 23.2, and there is no new migration.

The Custom Way

Without the admin site, every correction page is written by hand. This illustration is a tiny editing function for events held in a dictionary, with the checks a real page would need: who may edit, one of Chapter 21’s rules, and a record of the change. Run it with any Python, and do not add it to the project:

illustration_only/by_hand.py (not part of the project)

FIELDS = ['title', 'capacity']
rows = {1: {'title': 'Python meetup', 'capacity': 40}}
log = []


def edit(user, row_id, changes):
    if not user['is_staff']:
        return 'refused'
    if int(changes.get('capacity', 1)) <= 0:
        return ['Capacity must be more than 0.']
    before = dict(rows[row_id])
    rows[row_id].update(changes)
    changed = [name for name in FIELDS
               if before[name] != rows[row_id][name]]
    log.append((user['email'], row_id, changed))
    return 'saved'


sam = {'email': 'sam@example.org', 'is_staff': True}
print(edit(sam, 1, {'capacity': 0}))
print(edit(sam, 1, {'capacity': 45}))
print(log)

Output

['Capacity must be more than 0.']
saved
[('sam@example.org', 1, ['capacity'])]

It works for one model with two fields. Now count what is missing. There is no page: no list, no form, no search, and no way to sign in. The capacity rule is copied from the model, so the two copies can drift apart. The permission check is one flag, written by hand, and every other model needs its own function with its own checks and its own log. The admin site does all of this from the model: it builds the pages, signs people in, asks the model for its rules, checks permissions per model, and writes the log. What it cannot know is Otahque’s decisions, such as “registrations are history”, and those are what this chapter writes.

Step 2: Sign in, and move the admin’s address

Start the development server, in any of the four shells, and leave it running:

Terminal

uv run python manage.py runserver

Open http://127.0.0.1:8000/admin/. The admin sends you to its sign-in page, /admin/login/?next=/admin/, which asks for an “Email address”, because Chapter 17 made the email the field people sign in with. Sign in with sam@example.org and the password you chose for Sam in Chapter 18. The page that opens is the admin’s index, headed “Django administration” and “Site administration”, and it lists one model: Groups, under “Authentication and Authorization”. Django’s auth app registers Groups itself. Otahque’s models are missing, and so are its users: Django registers its own user admin only for its own User model, and Chapter 17 replaced that model with Otahque’s.

Before registering anything, give the admin site an address of your choosing. Every Django project starts with the admin at /admin/, so automated scripts that probe websites try that address first. An address that is hard to guess does not make the admin secure, but it keeps those scripts away, and the address is a setting that differs between your computer and each deployment, which is what Chapter 8’s .env file is for. Stop the server with Ctrl+C. Open config/settings.py and add these lines after the ALLOWED_HOSTS setting:

config/settings.py (after ALLOWED_HOSTS)

# The admin site's path: admin/ locally, and a path that is
# hard to guess in each deployment. It ends with /.
ADMIN_URL = config('DJANGO_ADMIN_URL', default='admin/')
if ADMIN_URL.startswith('/') or not ADMIN_URL.endswith('/'):
    raise ImproperlyConfigured(
        'DJANGO_ADMIN_URL must end with / and not start '
        'with it; see .env.example.'
    )

config() reads DJANGO_ADMIN_URL from the environment or from .env, and uses admin/ when it is missing. The check refuses a value that would build a broken pattern: Django’s URL patterns never start with /, and this one must end with / so that the admin’s own pages, such as admin/login/, follow it. Then open .env.example and add three lines at the end, so the next developer knows the setting exists:

.env.example (add at the end)

# The admin site's path, ending with /. Keep admin/ locally;
# choose a path that is hard to guess for each deployment.
DJANGO_ADMIN_URL=admin/

Add the same setting to your own .env, at the end, keeping admin/ on your computer:

.env (add at the end)

DJANGO_ADMIN_URL=admin/

On a deployed Otahque, the value is a path of its own, such as manage-7Kq2/, chosen once and kept out of the code like the secret key. Now replace config/urls.py with:

config/urls.py

"""
URL configuration for the Otahque project.
"""
from django.conf import settings
from django.contrib import admin
from django.urls import include, path

admin.site.site_header = 'Otahque administration'
admin.site.site_title = 'Otahque admin'

urlpatterns = [
    path(settings.ADMIN_URL, admin.site.urls),
    path('', include('events.urls')),
]

The pattern now comes from the setting. The two admin.site lines replace Django’s default title, “Django administration”, with Otahque’s own in the header and in the browser tab. Check the project:

Terminal

uv run python manage.py check

Output

System check identified no issues (0 silenced).

Common Error: the address has no final slash

With DJANGO_ADMIN_URL=admin in .env, every command stops with django.core.exceptions.ImproperlyConfigured: DJANGO_ADMIN_URL must end with / and not start with it; see .env.example. That is the check you just wrote, refusing a value that would make the admin’s pages unreachable. Add the final /. A value set in your shell’s environment wins over .env, so if .env looks right, check the environment too.

Start the server again and reload the admin. The header now reads “Otahque administration”, and the page is unchanged otherwise. Leave the server running while you work, and stop and start it if a page looks stale; the tests below do not need it.

Step 3: Write the access tests first

The first tests decide who may enter, before any model is registered. They live in config/tests.py, beside Chapter 18’s migration test, because they are about the whole admin site rather than one app. They need the address of admin pages, and Django names those addresses in one pattern: admin: followed by the app’s label, the model’s name in lower case, and the page, such as admin:events_event_changelist for the event list and admin:events_event_change for one event’s page. Add a helper to events/tests.py, after save_event(), separated from it and from the next function by two blank lines, so every test file can build those names the same way:

events/tests.py (after save_event)

def admin_url(model, page, *args):
    """An admin page's address, such as an event's page."""
    meta = model._meta
    name = f'admin:{meta.app_label}_{meta.model_name}_{page}'
    return reverse(name, args=args)

model._meta is the model’s description, which Django fills in from the class; app_label is events and model_name is event. Then open config/tests.py and replace its imports, the four lines from from io import StringIO to from django.test import TestCase, with:

config/tests.py (top of the file, replaced)

class AdminAccessTests(TestCase):
    @classmethod
    def setUpTestData(cls):
        cls.event = save_event()

    def sign_in(self, email, **flags):
        User.objects.create_user(
            email, PASSWORD, display_name='Test', **flags
        )
        return self.client.post(
            reverse('admin:login'),
            {'username': email, 'password': PASSWORD},
        )

    def staff(self):
        return User.objects.create_user(
            'helper@example.org', display_name='Helper',
            is_staff=True,
        )

    def test_visitor_is_sent_to_sign_in(self):
        index = reverse('admin:index')
        self.assertRedirects(
            self.client.get(index),
            f"{reverse('admin:login')}?next={index}",
        )

    def test_member_is_refused(self):
        response = self.sign_in('raj@example.org')
        self.assertContains(response, REFUSED)

    def test_inactive_staff_is_refused(self):
        response = self.sign_in(
            'old@example.org', is_staff=True,
            is_active=False,
        )
        self.assertContains(response, REFUSED)

    def test_staff_flag_alone_grants_nothing(self):
        helper = self.staff()
        self.client.force_login(helper)
        response = self.client.get(reverse('admin:index'))
        self.assertContains(
            response, 'permission to view or edit anything'
        )
        response = self.client.get(
            admin_url(Event, 'changelist')
        )
        self.assertEqual(response.status_code, 403)
        self.assertFalse(
            helper.organizer_assignments.exists()
        )

    def test_view_permission_has_no_save(self):
        helper = self.staff()
        helper.user_permissions.add(
            Permission.objects.get(codename='view_event')
        )
        self.client.force_login(helper)
        url = admin_url(Event, 'change', self.event.pk)
        response = self.client.get(url)
        self.assertContains(response, 'Python meetup')
        self.assertNotContains(response, 'name="_save"')
        response = self.client.post(url, {'capacity': 1})
        self.assertEqual(response.status_code, 403)

Each test is one rule from Figure 23.1. A visitor is sent to sign in, with ?next= holding the page they asked for. A member and an inactive staff account both get the admin’s refusal: the first because is_staff is false, the second because Django refuses inactive accounts before it looks at anything else. sign_in() posts the email and password to the admin’s sign-in page, as a browser does. The last two tests use force_login(), which signs an account in without a password. A staff account with no permissions sees “You don’t have permission to view or edit anything.” on the index, is refused the event list with status 403, and organizes nothing: organizer_assignments is Chapter 20’s reverse relation, and it is empty. With only view_event, the event page opens with no Save button, and a forged save is refused. Permission.objects.get(codename='view_event') fetches one of the rows Chapter 18’s migrations created. Step 4: Register events

Events come first, because the administrator corrects them most. The tests describe the list and the event page before they exist. Add a function and a class at the end of events/tests.py:

events/tests.py (add at the end)

def event_form(event, **changes):
    """What the admin's event page sends; times in UTC."""
    data = {
        'title': event.title,
        'status': event.status,
        'starts_at_0': f'{event.starts_at:%Y-%m-%d}',
        'starts_at_1': f'{event.starts_at:%H:%M}',
        'ends_at_0': f'{event.ends_at:%Y-%m-%d}',
        'ends_at_1': f'{event.ends_at:%H:%M}',
        'timezone': event.timezone,
        'location': event.location,
        'capacity': event.capacity,
        'registrations-TOTAL_FORMS': 0,
        'registrations-INITIAL_FORMS': 0,
    }
    data.update(changes)
    return data

                   status=Event.Status.DRAFT)

    def setUp(self):

                             self.workshop.pk)

    def test_list_shows_drafts_local_start_and_places(self):

    def test_times_are_typed_in_utc(self):

Under the Hood: why the form skipped Chapter 21’s rule

When the admin saves, the form calls full_clean() with exclude, the set of model fields that are not on the form, and full_clean() passes it on to validate_constraints(). A constraint that names an excluded field is skipped, because the value it would check may not be the value that is saved. On the add page, the form holds event and member but not revoked_at, which the “one current assignment” constraint names in its condition. On the change page, assigned_at is read-only, so the form does not hold it, and the “revoked after assigned” constraint names it. Both rules were skipped, and the database refused the rows, as it should. The rules were never at risk; the message was.

The fix belongs on the model, where Chapter 21’s rules live, and it is one method. Open events/models.py and add it inside OrganizerAssignment, after __str__(), separated by one blank line:

    def validate_constraints(self, exclude=None):
        """Check every rule, even for fields a form omits."""
        super().validate_constraints(exclude=None)

        return False

The audit log’s admin class lives in accounts/admin.py for a practical reason: autodiscover() reads admin.py only from installed apps, and config is not one. The log records what accounts did, so the accounts app owns its page. Every permission method returns False, so the page is read-only for everyone. Step 8: Record the boundary

The configuration is in the code; the reasons belong in a design note that the next developer reads before changing it. Create docs/design/admin.md, beside Chapter 15’s ERD:

docs/design/admin.md

# Otahque admin site

Status: Drafted in Chapter 23, for review.
Who: the community administrator only. Organizers use
Otahque's own pages (Chapter 26); visitors and members
never use the admin site.

## What the admin may do

- Events: view, add, and change; delete only an event
  with no registrations or assignments; no bulk actions.
  Times are typed in UTC; the list and the event page
  show the local start in the event's own zone.
- Registrations: view only. Places are created and
  cancelled by Otahque's own pages (Chapters 31, 33).
- Organizer assignments: view, add, and revoke by
  setting revoked_at; never deleted (PR-6).
- Users: view and change email, display name, active,
  staff, groups, and permissions. No add page (accounts
  come from createsuperuser or create_user until
  Chapter 27), no delete (deactivate instead), and the
  password is never shown or set here.
- Log entries: view only. The audit log of admin saves.

## What the admin does not protect

- The admin log records admin saves only: not the
  shell, scripts, migrations, Otahque's own pages, or
  sign-ins. Its rows can be changed by anyone with
  database access. Business audit trail: Chapters 30, 65.
- Permissions are per model, not per event, so the
  admin cannot limit an account to its own events.
- A rule that is not in the model is not applied here.

## Best practices

- Done (Chapter 23): admin path from DJANGO_ADMIN_URL,
  not the guessable admin/, in each deployment.
- Done (Chapter 23): per-model limits in code, each
  proved by a test, superusers included.
- Done (Chapter 23): password never shown or set on
  the user page.
- Done (Chapter 23): read-only audit log page.
- Planned (Chapter 30): an administrator group with
  only the permissions the role needs; no shared
  superuser accounts.
- Planned (Chapters 29, 59): two-factor sign-in,
  required for staff, through django-allauth's MFA.
- Planned (Chapters 59, 60): sign-in rate limits,
  HTTPS only, secure cookies, and security headers.
- Planned (Chapter 63): deployment review of the admin
  path, staff accounts, and access logs.
- Rule: the superuser password is used locally only;
  deployed accounts are created per person.

The second half is a checklist of admin best practices, each marked with where it stands. Four are done in this chapter, and the rest are planned for the chapters named. Writing down what is not done yet is part of the design: “the admin site is safe” would be a claim nobody can check, and this list can be.
