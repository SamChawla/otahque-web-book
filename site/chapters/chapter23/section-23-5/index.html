Checkpoint: Quiz and Challenge

Quiz

Que. 2 An account has is_staff set and holds no permissions. What does it see after signing in to the admin site, and does it organize any event?

Flip to check your answerFold answer back

Answer. The index says it has no permission to view or edit anything, and every model page refuses it with 403. It organizes nothing: organizing is an OrganizerAssignment row, which is_staff does not create, and only Otahque’s own pages will read it.

Que. 3 Sam types 18:30 into the Starts at field of the Python meetup in Leeds, for a date in July. What is stored, and what does a visitor see?

Flip to check your answerFold answer back

Answer. The admin reads the time in the current zone, UTC, so 18:30 UTC is stored. In July, Leeds is on British Summer Time, one hour ahead of UTC, so the public page shows 19:30. The Local start column would show 19:30 BST and reveal the mistake.

Que. 4 Why did RegistrationAdmin refuse change permission, when Sam is a superuser who holds every permission?

Flip to check your answerFold answer back

Answer. A has_change_permission() method that returns False refuses the action for every account, superusers included. Registrations are history: places are made and cancelled by the rules of Chapters 31 and 33, so the admin may only read them.

Que. 5 In Step 5, adding a second current assignment raised IntegrityError instead of showing Chapter 21’s message. Why, and what changed?

Flip to check your answerFold answer back

Answer. The add page’s form holds event and member but not revoked_at, which the “one current assignment” constraint names, so full_clean() skipped the constraint, and the database refused the row. OrganizerAssignment.validate_constraints() now checks every constraint, whatever the form holds, so the message appears on the page.

Que. 6 Which of these appear in the audit log: a location changed in the admin, a registration created in the shell, and Sam signing in?

Flip to check your answerFold answer back

Answer. Only the location change. The log records adds, changes, and deletes made through the admin’s pages; the shell and sign-ins write nothing there.

Mini-Challenge

Que. 7 The community plans to give a second administrator an account that may only read registrations and the audit log. Predict which models the admin index will list for an account with is_staff and the two permissions view_registration and view_logentry, and whether it may open the registration list and the event list. Then check your prediction with a practice file that creates the account inside a transaction and rolls it back.

Flip to check your answerFold answer back

Answer. The index lists Log entries and Registrations, each with a View link. The account may open the registration list, and the event pages refuse it with 403. One file that checks it, run with uv run python ../practice/challenge.py:

../practice/challenge.py

import setup_django
from django.contrib import admin
from django.contrib.auth.models import Permission
from django.db import transaction
from django.test import RequestFactory

from accounts.models import User
from events.models import Event
from registrations.models import Registration

CODES = ['view_registration', 'view_logentry']
with transaction.atomic():
    reader = User.objects.create_user(
        'reader@example.org', display_name='Reader',
        is_staff=True,
    )
    reader.user_permissions.add(
        *Permission.objects.filter(codename__in=CODES)
    )
    request = RequestFactory().get('/')
    request.user = User.objects.get(pk=reader.pk)
    print([model['name']
           for app in admin.site.get_app_list(request)
           for model in app['models']])
    for model in (Registration, Event):
        model_admin = admin.site.get_model_admin(model)
        allowed = model_admin.has_view_permission(request)
        print(model.__name__, allowed)
    transaction.set_rollback(True)
kept = User.objects.filter(email='reader@example.org')
print(kept.exists())

Output

['Log entries', 'Registrations']
Registration True
Event False
False

get_app_list() is the list the index page draws, so its model names are what the account sees, and has_view_permission() is the check each list page makes before it opens. The account is fetched again before the checks because Django caches an account’s permissions the first time it asks. transaction.atomic() with set_rollback(True) undoes the account and its permissions, so the last line confirms nothing was kept.

What We Learned

  • The admin site is the administrator’s tool, built from the models; Otahque’s own pages serve visitors, members, and organizers.
  • is_staff only lets an account sign in to the admin. Permissions decide each page, and organizing is an assignment row, not a flag.
  • A ModelAdmin chooses list columns, filters, search, order, and fields; @admin.display adds computed columns.
  • has_add_permission() and its siblings state rules for every account, superusers included, and each refusal deserves a test.
  • Times typed in the admin are read in the current zone, UTC; label the fields and show the local time beside them.
  • The admin’s forms call full_clean(), so model rules reach the page, but a constraint naming a field the form omits is skipped unless the model checks it.
  • Related columns, inlines, and lists need joined queries; assertNumQueries keeps each page’s count fixed.
  • History stays read-only: registrations are viewed, assignments revoked, users deactivated, and “Delete selected” is removed.
  • LogEntry records admin saves only; a read-only page makes it Otahque’s audit log, and a business trail comes later.
  • The admin’s address belongs in settings, read from the environment, and its remaining risks belong in a design note.
