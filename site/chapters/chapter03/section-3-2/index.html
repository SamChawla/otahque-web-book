3.2 Finding and reaching a web address

Soni receives a link to a workshop. Before following it, she wants to know which site it opens and whether it points to the event she expects. Reading an address is useful to a visitor; later, it also helps a developer distinguish a wrong destination from a missing page.

Read the address in parts

A web address is a Uniform Resource Locator, or URL. Consider the fictional address below. It is an illustration to read on paper, not a working Otahque route or an instruction to visit a site.

https://otahque.example/events/42/?view=details#venue

The scheme, https, names the protocol: the agreed rules for the exchange. Here it is HTTPS, a protected form of the Hypertext Transfer Protocol, or HTTP; the end of this section explains what that protection covers. The host, otahque.example, names the destination. The path, /events/42/, identifies a resource at that host. The query, view=details, supplies an extra value after the question mark. The fragment, venue, follows the hash sign and can identify a position within the returned page. Query and fragment are optional.

For this example, the site would decide what event 42 and view=details mean. A readable path is not evidence that a matching file exists on disk. The server can use the path to choose application behaviour. The fragment is not sent in the HTTP request; the browser uses it after obtaining the resource.

Que. 7 If Soni changes only #venue to #schedule, is she asking for a different host?

Show answerHide answer

Answer. No. The host has not changed, so the browser is still dealing with the same site. The fragment points within the resource and is handled by the browser. Whether the page contains a matching location is a separate question.

Find the host before asking for its page

Computers use network addresses to communicate. An Internet Protocol address, shortened to IP address, is one kind of address used to reach a network destination. A memorable host name and an IP address are different things. The Domain Name System, or DNS, provides name lookups that can supply addresses associated with a host.

In a simplified fresh visit, the browser and operating system obtain an address for the host, establish the required connection, and then ask the web service for a resource. A DNS lookup does not return the event description and does not decide whether Soni may register. Those are later jobs.

The lookup step may use a previously saved result. A host can also have more than one address, so the diagram is not a claim that each visit performs a new lookup or always reaches the same machine. The useful distinction is between finding where to connect and asking the connected service what to return.

Que. 8 The host lookup fails before an event request can be made. Should Soni conclude that the workshop has been deleted?

Show answerHide answer

Answer. No. The failure concerns reaching the named host. It says nothing about whether the workshop exists. First check the spelling of the host and whether other sites can be reached; do not change or delete event data to solve a connection problem.

What HTTPS protects

HTTP defines how web requests and responses are written and exchanged. HTTPS uses Transport Layer Security, or TLS, to encrypt communication between the client and server. Encryption makes the transmitted content unreadable to someone who merely observes that protected connection.

This protection matters when Sai later signs in. It does not decide whether Sai owns a registration, whether a place remains, or whether the displayed event details are truthful. Those questions belong to the application and its people. A protected connection to the wrong site is still the wrong destination, so Soni must read the host as well as the scheme.

Que. 9 Does HTTPS allow Raj to cancel another member’s place?

Show answerHide answer

Answer. No. HTTPS protects the exchange in transit. Otahque must still identify Raj and enforce the rule that he can cancel only his own registration. Transport protection and permission checks solve different problems.

Try it yourself

On paper, annotate the fictional address above. Circle the host, underline the event path, and mark the optional query and fragment. Then describe which part changes if Soni opens event 43 on the same host. No site visit, installation, or file change is required.

Que. 10 What should the annotation and changed address show?

Show answerHide answer

Answer. Circle otahque.example and underline /events/42/. Mark view=details as the query and venue as the fragment. For event 43 in this invented naming scheme, the path becomes /events/43/; the host stays the same. This shows a different resource on the same host, not a different DNS name.
