Checkpoint: Quiz and Challenge

Quiz

Que. 24 Which part of https://otahque.example/events/42/?view=details#venue is never sent to the server?

Flip to check your answerFold answer back

Answer. The fragment, venue. The browser keeps it to choose a place on the page.

Que. 25 Why can one page visit produce many requests?

Flip to check your answerFold answer back

Answer. The page document names other resources, such as stylesheets, images, and scripts, and the browser requests each one separately.

Que. 26 What is the difference between a GET request and a POST request?

Flip to check your answerFold answer back

Answer. GET asks to read a resource and should not request a change to product state. POST submits data for the server to process, such as a registration.

Que. 27 Why does the server answer a successful registration with a redirect?

Flip to check your answerFold answer back

Answer. So that the browser then makes a GET for the result page. Refreshing that page repeats only the safe GET, not the registration.

Que. 28 After a lost reply, what should Sai do before trying again?

Flip to check your answerFold answer back

Answer. Check her registrations. The request may already have been accepted, so the current state, not a repeated request, tells her the outcome.

Mini-Challenge

On paper, write the sequence of messages when Raj cancels his registration: each request with its method and path, each response with its status, and what the server checks before it changes anything. Use illustrative paths, as the chapter does. Then mark what Raj should see if the cancellation deadline has passed.

Que. 29 What would a good sequence show?

Flip to check your answerFold answer back

Answer. Raj’s browser sends POST to an illustrative cancellation address. The server checks that Raj is signed in, that the registration is his and still active, and that the deadline has not passed; it records the cancellation and replies 303 with the location of his registrations page. The browser sends GET for that page and receives 200 with the cancelled status. If the deadline has passed, the server changes nothing and replies with a page explaining why; Raj’s registration stays active.

What We Learned

  • A browser asks and displays; a web server receives requests and returns responses, and one page visit can involve many exchanges.
  • An address has a scheme, host, path, query, and fragment; DNS finds the host’s address before the page request, and HTTPS protects the exchange.
  • GET reads and POST requests a change; a redirect after a POST keeps a refresh from repeating the change.
  • The browser can give helpful feedback, but identity, access, time windows, and capacity are decided and recorded on the server.
  • A request can be accepted, refused, or left uncertain when a reply is lost; checking the current state resolves the uncertainty.
  • The browser’s developer tools show the real exchanges, which is better evidence than the screen alone.
