3.3 Asking for information and requesting changes

Soni reads the workshop page. Sai, who already has an account in our proposed application, wants to register. Both actions involve messages, but they have different purposes. Reading should not silently consume a place. Registration asks the application to change its records.

A request has an action as well as an address

An HTTP method names the kind of action requested. GET asks for information about a resource. POST sends data for the server to process and is commonly used for actions that change application state. State means the information the application currently holds, such as which members have active registrations.

For Otahque, opening an event is a reading action. Submitting a registration is a request for a change. A form is a page element through which a person supplies information or submits an action. The browser translates its submission into a request; the application must decide whether to accept it.

Choosing POST does not make a request trustworthy, encrypt it, or prevent a second submission. HTTPS provides transport protection; application checks enforce the rules. Repeating a POST can have further effects unless the application handles repetition correctly. This is why Chapter 2’s duplicate-registration requirement must become a server-side check later.

Que. 11 Should following a link to read an event register the visitor as a side effect?

Show answerHide answer

Answer. No. Reading the event is a GET-style action. Registration should require a deliberate request for the change. If simply reading a link took a place, a visitor could register unintentionally while exploring the site.

The message carries context and content

A request identifies a target and method, and can carry headers: named pieces of information about the message. It may also have a body containing submitted data. A response carries a status code, headers, and sometimes a body. For a successful event-page request, the body can contain HTML; for an image request, it can contain image data.

A header named Content-Type describes the format of a message’s body. For now, think of it as a label helping the recipient interpret what arrived. The body is the content itself. A header and body have different roles, just as a document’s format label differs from the document’s text. We will read actual request objects when we reach Django views.

Read the response without over-interpreting it

A status code is a three-digit result attached to an HTTP response. Table 3.1 introduces a small useful set. These are general meanings, not final choices for every Otahque error or policy.

A browser connection error is different from receiving a 404 response. With a 404, a server has sent an HTTP response. A connection failure may prevent an HTTP response from arriving at all. Also, receiving 200 for a page does not prove that a registration was created: a page can successfully explain why an application action was refused.

Que. 12 Sai receives a page explaining that registration is closed. The page arrived successfully. Which result matters to her?

Show answerHide answer

Answer. The application result: she does not have a newly confirmed place. Successful delivery of a page and successful registration are different observations. She should read the result message rather than infer a booking from the fact that a page appeared.

A redirect asks the browser to make another request

A redirect is a response that points the browser towards another resource. One useful pattern after form processing is to return a 303 response with a Location header naming a result page. The browser then fetches that page with GET. In Figure 3.6, the result is a separate reading request after the submitted action.

Refreshing the resulting GET page normally reads it again rather than resubmitting the earlier form. This pattern helps the user experience, but it does not enforce the one-registration rule by itself. Sai could submit again from another tab, or a request could be repeated before the redirect arrives. The application still needs duplicate handling.

Que. 13 Does a redirect remove the need for a duplicate-registration check?

Show answerHide answer

Answer. No. It separates form submission from the page subsequently displayed. It does not prevent every repeated submission. The server must still enforce the rule about one active registration per member and event.

Try it yourself

Classify these proposed Otahque actions on paper: Soni reads event details; Sai submits a registration; Raj submits a cancellation; Sam reads the list for an event he manages. For each, say whether it asks to read or requests a change, then name GET or POST as the method to consider. Do not perform these actions on a live site.

Que. 14 How should the four actions be classified?

Show answerHide answer

Answer. Soni reads details: reading, GET. Sai registers: change request, POST. Raj cancels: change request, POST. Sam reads his event’s list: reading, GET. Reading can still require permission: GET does not mean that every visitor may see Sam’s list.
