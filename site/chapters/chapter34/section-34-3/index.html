How We Build It

Start from Chapter 33, in the folder containing manage.py, with Otahque on PostgreSQL 18, 354 passing tests, every migration applied, and the work committed. Two development packages are added: coverage.py 7.17.4 and tblib 3.2.2. No model or migration changes. Each app’s tests.py becomes a tests/ package; the new files are config/helpers.py, events/tests/test_locking.py, config/tests/test_acceptance.py, check.py, .github/workflows/ci.yml, docs/testing.md, docs/acceptance/M2.md, and docs/release-checklist.md, and pyproject.toml, .gitignore, templates/base.html, and the stylesheet source change. The visible result: a “Skip to the main content” link for keyboard users, and messages coloured by what they say. The chapter’s checks ran in Windows PowerShell 5.1 and Git Bash against PostgreSQL 18.3, and in GitHub Actions on Ubuntu 24.04 against PostgreSQL 18.

The Custom Way

CI begins where your laptop’s history does not: with a fresh copy of the repository and nothing else. Make one by hand, beside your project, and try to use it:

Terminal

git clone . ../otahque-clean
cd ../otahque-clean
uv sync --locked
uv run python manage.py check

Output

Cloning into '../otahque-clean'...
Using CPython 3.14.9
Creating virtual environment at: .venv
Installed 24 packages in 10.55s
...
django.core.exceptions.ImproperlyConfigured: Set
    DJANGO_SECRET_KEY; see .env.example.

Git copied every committed file and uv installed exactly the locked packages, but Django refuses to start: the secret key lives in .env, which Git never records (Chapter 8). The clean copy also has no database settings, so it would fall back to SQLite. This is precisely what a CI machine sees, and why the workflow in Step 10 must supply both. Go back to your project folder and delete the copy (Remove-Item -Recurse -Force ../otahque-clean in PowerShell, rm -rf ../otahque-clean elsewhere).

Step 2: Move the tests into packages

A package lets each app keep several test files: the old tests in one, and each new subject in its own. Move each app’s file into a tests/ folder with an empty __init__.py, which makes the folder a package. git mv moves the file and tells Git it was moved, so its history follows it.

PowerShell

# PowerShell
$apps = 'accounts', 'audit', 'config', 'events', 'registrations'
foreach ($app in $apps) {
    New-Item -ItemType Directory "$app/tests" | Out-Null
    New-Item "$app/tests/__init__.py" | Out-Null
    git mv "$app/tests.py" "$app/tests/test_$app.py"
}

Terminal

# Git Bash, macOS, Linux, WSL
for app in accounts audit config events registrations; do
    mkdir "$app/tests"
    touch "$app/tests/__init__.py"
    git mv "$app/tests.py" "$app/tests/test_$app.py"
done

Each file keeps every test it had; only its address changes, from events.tests to events.tests.test_events. Moving and splitting are two changes: do the move now, and split a file further when you next work in it. Step 3: One module for shared helpers

Helpers that several apps’ tests use belong in one module that belongs to no single app. Create config/helpers.py. Its name does not start with test, so the runner never collects it as tests; a name such as testing.py would match the runner’s test*.py pattern.

config/helpers.py

"""Helpers that more than one app's tests use.

Not a test module: its name does not start with "test",
so the test runner never collects it. Each helper makes
data or a request the way the earlier chapters' tests
did; one copy here replaces the imports from
events.tests that broke when the tests moved.
"""
from datetime import UTC, datetime, timedelta

from django.contrib.auth import get_user_model
from django.contrib.auth.models import Group
from django.urls import reverse

from events.forms import EventForm
from events.models import Event, OrganizerAssignment

User = get_user_model()

SAI_PASSWORD = 'a-long-safe-pass-123'


def save_event(**changes):
    """Save a published event; keywords replace defaults."""
    fields = {
        'title': 'Python meetup',
        'starts_at': datetime(2026, 11, 19, 18, 30,
                              tzinfo=UTC),
        'timezone': 'Europe/London',
        'location': 'Leeds Central Library',
        'capacity': 40,
        'status': Event.Status.PUBLISHED,
    }
    fields.update(changes)
    fields.setdefault(
        'ends_at', fields['starts_at'] + timedelta(hours=2)
    )
    return Event.objects.create(**fields)


def in_group(email, group, **flags):
    """Add a member with SAI_PASSWORD to the named group."""
    name = email.split('@')[0].title()
    user = User.objects.create_user(
        email, SAI_PASSWORD, display_name=name, **flags
    )
    user.groups.add(Group.objects.get(name=group))
    return user


def admin_url(model, page, *args):
    """Return an admin page's address, such as an event's."""
    meta = model._meta
    name = f'admin:{meta.app_label}_{meta.model_name}_{page}'
    return reverse(name, args=args)


def event_form(event, **changes):
    """Build what the admin's event page sends; UTC times."""
    data = {
        'title': event.title,
        'status': event.status,
        'starts_at_0': f'{event.starts_at:%Y-%m-%d}',
        'starts_at_1': f'{event.starts_at:%H:%M}',
        'ends_at_0': f'{event.ends_at:%Y-%m-%d}',
        'ends_at_1': f'{event.ends_at:%H:%M}',
        'timezone': event.timezone,
        'location': event.location,
        'capacity': event.capacity,
        'registrations-TOTAL_FORMS': 0,
        'registrations-INITIAL_FORMS': 0,
        'seen_version': event.version,
    }
    data.update(changes)
    return data


def remove_selected(client, *assignments):
    """Run the admin's Remove selected organizers action."""
    return client.post(
        admin_url(OrganizerAssignment, 'changelist'),
        {'action': 'remove_selected',
         '_selected_action': [a.pk for a in assignments]},
        follow=True,
    )


def as_sent(event, **changes):
    """Return what the edit page sends, before any change."""
    form = EventForm(instance=event)
    data = {}
    for name in form.fields:
        value = form[name].value()
        if isinstance(value, datetime):
            value = f'{value:%Y-%m-%dT%H:%M}'
        # A blank time is sent as an empty box.
        data[name] = '' if value is None else value
    # The version the page was opened at (Chapter 33).
    data['version'] = event.version
    return data | changes


def outcome(response):
    """Name a response as the permission matrix names it."""
    code = response.status_code
    if code == 302 and response.url.startswith(
            reverse('account_login')):
        return 'sign in'
    return {200: 'ok', 302: 'ok'}.get(code, str(code))

Step 4: Measure coverage

coverage.py is needed by developers and CI, not by the running site, so add it as a development dependency. uv records those in a separate group in pyproject.toml and in uv.lock, and installs them with uv sync unless asked not to.

Terminal

uv add --dev coverage==7.17.4

Output

Resolved 26 packages in 184ms
Installed 1 package in 973ms
 + coverage==7.17.4

coverage run runs a Python program while measuring it. Run the suite through it, then ask for the report:

Terminal

uv run coverage run manage.py test --parallel
uv run coverage report

Output

Name                     Cover
----------------------------------------------------
events\models.py           36%
events\views.py            28%
...
----------------------------------------------------
TOTAL                      34%

The book prints two rows and the total. events/models.py at 36% would be alarming, and it is false. With --parallel, the tests run in worker processes, and coverage.py measured only the main process, which mostly waited. Tell it to follow the workers. Add to the end of pyproject.toml:

pyproject.toml

[tool.coverage.run]
# Measure the project's own code, not its tests.
source = ["accounts", "audit", "config", "events",
          "registrations"]
omit = ["*/migrations/*", "*/tests/*", "config/helpers.py"]
branch = true
# test --parallel runs the tests in several processes:
# each writes its own data file, and combine joins them.
parallel = true
concurrency = ["multiprocessing", "thread"]

[tool.coverage.report]
show_missing = true
skip_covered = true

source limits the report to Otahque’s apps, omit leaves out migrations and the tests themselves, and branch = true also records which way each if went. With parallel = true each process writes its own data file, and concurrency names how the program runs in parallel: in several processes, and, in the race tests, in threads. Those data files and the HTML report must not be committed. Add to .gitignore:

.gitignore


# coverage's data files and HTML report (Chapter 34)
.coverage
.coverage.*
htmlcov/

Now measure again. erase removes the old data, and combine joins the workers’ files before the report:

Terminal

uv run coverage erase
uv run coverage run manage.py test --parallel
uv run coverage combine
uv run coverage report

def database_error(sqlstate):
    """Return Django's error for a psycopg one with sqlstate."""
    error = OperationalError('the row could not be locked')
    error.__cause__ = errors.lookup(sqlstate)()
    return error


class LockErrorTests(TestCase):
    """locked() calls only a lock timeout "busy"."""

        """Make the row lock fail with that database code."""
        rows = mock.Mock()

            Event.objects, 'select_for_update',
            return_value=rows,

        with self.lock_fails_with('55P03'):
            with self.assertRaises(ValidationError) as caught:

@contextmanager
def meet_after_counting(timeout=2):
    """Make each request wait, after counting, for the other.

    Without a lock both count before either inserts, so
    the race happens every time. With the lock the other
    request is still waiting for the event row, so the
    meeting times out and the requests take turns. The
    lock's time limit is raised meanwhile: on a busy
    machine the wait for the row can pass 3 s, and these
    tests are about turns, not "busy".
    """
    barrier = threading.Barrier(2, timeout=timeout)
    count = Event.places_taken

    def counted(event):
        taken = count(event)
        try:
            barrier.wait()
        except threading.BrokenBarrierError:
            pass
        return taken

    with mock.patch.object(Event, 'places_taken', counted):
        with mock.patch('events.models.LOCK_TIMEOUT', '30s'):
            yield

@contextmanager turns a function with one yield into something with can use: both patches are in place for the body of the with block, and both are undone after it, even if the test fails.

config/tests/test_acceptance.py

"""The acceptance trace names only tests that exist."""
import re
from importlib import import_module

from django.conf import settings
from django.test import SimpleTestCase

TRACE = settings.BASE_DIR / 'docs/acceptance/M2.md'
APPS = ['accounts', 'audit', 'config', 'events',
        'registrations']
NAME = re.compile(r'`(\w+Tests)\.(test_\w+)`')


def test_classes():
    """Yield every test class in the apps' tests packages."""
    for app in APPS:
        folder = settings.BASE_DIR / app / 'tests'
        for path in sorted(folder.glob('test*.py')):
            module = import_module(f'{app}.tests.{path.stem}')
            yield from vars(module).values()


class TraceTests(SimpleTestCase):
    """docs/acceptance/M2.md, checked against the tests."""

    def test_every_named_test_exists(self):
        names = NAME.findall(TRACE.read_text(encoding='utf-8'))
        self.assertGreater(len(names), 40)
        found = {(c.__name__, m) for c in test_classes()
                 if isinstance(c, type) for m in dir(c)}
        missing = [f'{c}.{m}' for c, m in names
                   if (c, m) not in found]
        self.assertEqual(missing, [])

It reads every name in backticks from the trace, imports every test module of the five apps, and lists any name that no class defines. assertGreater(len(names), 40) guards against a trace that loses its names entirely. Also add the short guide to how Otahque is tested, docs/testing.md, for whoever joins next:

docs/testing.md

# How Otahque is tested

## Where tests live

Each app has a `tests/` package. Its `test_<app>.py` holds
the tests of the earlier chapters; a new subject gets its
own `test_<subject>.py` beside it. Helpers that more
than one app's tests use live in `config/helpers.py`, which
the runner does not collect: its name does not start with
"test". Helpers for one app stay in that app's tests.

## Which tool for which question

| Question | Tool |
|---|---|
| Is this function right, no database? | `SimpleTestCase` |
| Is this rule right, with the database? | `TestCase` |
| Does this page answer as it should? | the test client |
| Does this middleware work alone? | `RequestFactory` |
| What if two requests overlap? | `TransactionTestCase` |
| Does a test class share costly rows? | `setUpTestData` |

`TestCase` undoes each test inside a transaction, so other
connections never see its rows; race tests need
`TransactionTestCase`, which commits and empties the tables
afterwards, and PostgreSQL.

## Commands

    uv run python check.py
    uv run python manage.py test --parallel --reverse
    uv run coverage run manage.py test --parallel
    uv run coverage combine
    uv run coverage report

Coverage is read, not targeted: a line that ran is not a
rule that was checked. docs/acceptance/M2.md names the
tests behind each rule.

Step 10: One command, then CI

The checks a change must pass are three commands. Put them in one file beside manage.py, so that you and CI run exactly the same thing. Create check.py:

check.py

"""Run the checks every change must pass, as CI does.

Usage: uv run python check.py
Runs Django's system checks, the migration check, and the
whole test suite, in that order. It stops at the first
check that fails and exits with that check's code, so CI
marks the run as failed.
"""
import subprocess
import sys

CHECKS = [
    ['manage.py', 'check'],
    ['manage.py', 'makemigrations', '--check', '--dry-run'],
    ['manage.py', 'test', '--parallel'],
]


def main():
    """Run each check; return the first failure's code."""
    for args in CHECKS:
        print('== python', ' '.join(args), flush=True)
        result = subprocess.run([sys.executable, *args])
        if result.returncode:
            print('== failed:', ' '.join(args))
            return result.returncode
    print('== all checks passed')
    return 0


if __name__ == '__main__':
    sys.exit(main())

makemigrations --check --dry-run fails if a model changed without a migration, and writes nothing. subprocess.run() runs each command with the same Python, and the first failure ends the script with its exit code, which is how CI knows the run failed.

        run: uv sync --locked
      - name: Create the databases (Chapter 32)
        run: |
          for name in otahque otahque_template; do
            psql -h localhost -U postgres -c \
              "CREATE DATABASE $name TEMPLATE template0
               LOCALE_PROVIDER builtin
               BUILTIN_LOCALE 'C.UTF-8'"

      - name: Make a secret key for this run only

Read it from the top. on: push runs it for every push to any branch, and for pull requests (Chapter 64). The job runs on Ubuntu 24.04, named exactly so that an upgrade is your decision. services starts PostgreSQL 18 in a container beside the job, and the health options make the steps wait until it answers. The env lines are the DB_* settings Chapter 32 introduced, here as environment variables instead of a .env file. actions/checkout and astral-sh/setup-uv are ready-made steps, each pinned to an exact release, and setup-uv installs the uv version the book uses. uv sync --locked installs exactly what uv.lock names, and fails if the lock no longer matches pyproject.toml. The databases are made as Chapter 32 made them, with the builtin C.UTF-8 locale. The secret key is made fresh for each run and never stored: the tests need a key, not your key. Common Error: the CI run fails before the tests

“Set DJANGO_SECRET_KEY” means the key step is missing or after the checks. A connection error on port 5432 means the services block or a DB_* line is wrong, or the health options were left out, so the checks started before PostgreSQL. uv sync --locked failing with “The lockfile needs to be updated” means pyproject.toml changed without uv lock: run uv lock locally, commit uv.lock, and push. Never change the workflow to uv sync without --locked to make it pass: that hides the stale lock instead of fixing it.

Step 12: The release checklist, and the tag

A release is a commit you can name and return to. Before naming one, run a checklist, and stop if any box stays empty. Create docs/release-checklist.md:

docs/release-checklist.md

# Release checklist

Run it before tagging a release. Every box must be ticked on
the commit you tag; a box you cannot tick stops the release.

## Checks

- [ ] `git status --short` prints nothing.
- [ ] `uv run python check.py` ends with "all checks passed"
      (system checks, migrations, the whole suite).
- [ ] `uv run python manage.py test --parallel --reverse`
      passes too: no test depends on the order.
- [ ] The race tests ran, not skipped: the suite used
      PostgreSQL.
- [ ] CI is green for this commit.
- [ ] docs/acceptance/M2.md matches what was tested, its
      known limits included.

## UI, at 390 and 1280 pixels wide

On the event list, an event page, My registrations, and the
new event and edit pages:
- [ ] Nothing scrolls sideways; text and buttons fit.
- [ ] Tab reaches "Skip to the main content" first, then
      every link, field, and button in order, each with a
      visible ring.
- [ ] Register and cancel can be done with the keyboard
      alone (Tab, Enter, Space).
- [ ] Messages say in words what happened; colour only
      repeats it.
- [ ] Text is readable at 200% zoom.

## Then

- [ ] Tag the commit: `git tag -a v0.1.0 -m "..."`.
- [ ] Push the tag: `git push origin v0.1.0`.

When something goes wrong

No recovery here touches your data: tests run in their own test database, coverage writes only its own files, and a CI machine is thrown away after each run.
