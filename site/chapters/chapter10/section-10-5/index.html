Checkpoint: Quiz and Challenge

Quiz

Que. 3 What is the difference between request.path and request.GET?

Flip to check your answerFold answer back

Answer. request.path is the requested path. request.GET contains query parameters supplied in the URL, regardless of the request method.

Que. 4 What does <int:event_id> provide to the view?

Flip to check your answerFold answer back

Answer. For a matching path it supplies the captured digits as an integer named event_id. It does not prove that a corresponding event exists.

Que. 5 What is the difference between printing a string and returning an HttpResponse?

Flip to check your answerFold answer back

Answer. Printing writes to the server’s output. Returning HttpResponse gives Django a response to send for the request.

Que. 6 Why can both /events/999/ and /events/abc/ return 404 for different reasons?

Flip to check your answerFold answer back

Answer. The integer route matches 999 and the view raises Http404 for the absent sample. The route does not match abc, so no detail view is selected for that path.

Que. 7 Does this plain-text sample establish safe HTML rendering for arbitrary input?

Flip to check your answerFold answer back

Answer. No. It uses fixed sample data and returns plain text. HTML and untrusted data require appropriate escaping and other controls, introduced as the application develops.

Mini-Challenge

Add a second sample in a separate copy of the project, so that your own checkpoint stays as it is. Work it out before reading the model answer.

Que. 8 In a separate copy of the project, add key 2 with the fictional title Django workshop to SAMPLE_EVENTS. What should /events/2/ return? How can you check that an absent sample still produces 404?

Flip to check your answerFold answer back

Answer. With the local server running, /events/2/ should return Sample: Django workshop as plain text. Run uv run python manage.py test events to retain the existing missing-event check, and visit /events/999/ if checking in a browser. Remove the temporary entry or keep the exercise in a separate copy so the next chapter starts from the documented checkpoint.

What We Learned

  • A function-based view receives a request and returns an HTTP response or raises a handled exception.
  • The URL converter passes a matching integer to the view; it does not check the sample dictionary.
  • The response has a status, headers, and a body; our sample is explicit plain text.
  • A missing item and an unmatched route can both produce 404 for different reasons.
  • Tests and browser checks offer complementary evidence.

Key terms

Use Table 10.3 to explain requests, responses, and not-found handling in your own words.

Explain which 404 comes from the view and which from routing, and what E means in a test run. Return to the relevant part if any result is missing.

Git Commit

When the checks pass, see what changed and stage the three files, in PowerShell, a macOS shell, or Linux/WSL Bash, beside manage.py. Read the staged changes, and press q to leave the listing:

Terminal

git status --short
git add events/tests.py events/views.py events/urls.py
git diff --cached

Keep your .env and its secret out of Git. Then record the commit. It stays on your computer; there is no remote push in this chapter:

Terminal

git commit -m "Add sample event detail view"
