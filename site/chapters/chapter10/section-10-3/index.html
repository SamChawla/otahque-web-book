How We Build It

Start from the Chapter 9 project in the directory containing manage.py, with your own .env, the locked environment, and the three existing routing tests passing. We will change events/tests.py, events/views.py, and events/urls.py. No package, model, migration, or database is added. The result is a plain-text sample at /events/1/ and a 404 for a missing sample.

The Custom Way

Before using Django’s request handling, consider this small illustration. Do not add it to the project: it has no HTTP server and does not construct Django responses.

illustration_only/choose_sample.py (not part of the project)

def choose_sample(event_id):
    if event_id == 1:
        return 'Sample: Python meetup'
    return 'not found'

The decision is straightforward, but returning the words not found alone does not make an HTTP response have status 404. Django supplies request and response objects and handles Http404 for us.

The Django Way

Step 1: Write the tests first

Open events/tests.py. Keep the entire RoutingTests class from Chapter 9. Add this new class after it, with two blank lines separating the classes:

events/tests.py (add after RoutingTests)

class EventDetailTests(SimpleTestCase):
    """One event by number, and the 404 for any other."""

    def test_sample_event(self):
        response = self.client.get('/events/1/')
        self.assertEqual(response.status_code, 200)
        self.assertContains(
            response, 'Sample: Python meetup'
        )
        self.assertTrue(
            response['Content-Type'].startswith('text/plain')
        )

    def test_missing_event(self):
        self.assertIs(
            resolve('/events/999/').func, views.event_detail
        )
        response = self.client.get('/events/999/')
        self.assertEqual(response.status_code, 404)

    def test_invalid_id(self):
        response = self.client.get('/events/abc/')
        self.assertEqual(response.status_code, 404)

.EF... reports the six tests in order. The E is new: test_missing_event stopped with an unexpected error, because its first line asks Django to resolve a route that does not exist yet. The F is the sample test receiving a 404. The invalid address already passes, because the URL dispatcher answers it. That first check in test_missing_event matters later: once the route exists, it shows that this test’s 404 comes from the view, not from a missing route. Read the failures, then continue; do not delete the tests.

Step 2: Write the view

Common Error: returning a string

A view must return a response object, not a Python string. return 'Sample' fails with AttributeError: 'str' object has no attribute 'get', which names neither the view nor the mistake, because the error appears later, when Django’s middleware handles the value. Forgetting return altogether gives a clearer message: The view events.views.event_detail didn't return an HttpResponse object.

Replace events/views.py with this complete file. The first two views are unchanged. The dictionary contains one controlled sample; .get() returns None when its key is missing.

events/views.py

"""The events app's views: one function per page."""
from django.http import Http404, HttpResponse

SAMPLE_EVENTS = {1: 'Python meetup'}


def home(request):
    """Welcome visitors to Otahque."""
    return HttpResponse('Welcome to Otahque.')


def event_list(request):
    """List Otahque's events."""
    return HttpResponse('Event list coming soon.')


def event_detail(request, event_id):
    """Show one event, or 404 if its number is unknown."""
    title = SAMPLE_EVENTS.get(event_id)
    if title is None:
        raise Http404('Sample event not found')
    return HttpResponse(
        f'Sample: {title}', content_type='text/plain'
    )

The f-string combines a fixed prefix and a title from our own fixed dictionary. The view does not place the request path or query string into the body. Setting content_type makes this example plain text; it does not make later HTML interpolation safe.

Step 3: Connect the detail route

Replace events/urls.py with the complete file below. Keep the existing namespace and both existing patterns. The argument name in the route, event_id, must match the view’s parameter name.

events/urls.py

"""Addresses of the events app's pages."""
from django.urls import path

from . import views

app_name = 'events'

urlpatterns = [
    path('', views.home, name='home'),
    path('events/', views.event_list, name='list'),
    path('events/<int:event_id>/', views.event_detail,
         name='detail'),
]

Terminal

Visit http://127.0.0.1:8000/events/1/ and expect Sample: Python meetup. Visit http://127.0.0.1:8000/events/999/ and expect 404. Visit http://127.0.0.1:8000/events/abc/ and expect 404 from an unmatched route. Stop the server with Ctrl+C. If Django warns about unapplied migrations, do not apply them here; the planned custom user comes first.

When something goes wrong

Preserve your work while diagnosing a failure. Compare the three files with the listings and save a separate copy before replacing anything. Correct one problem, then rerun the full test suite. Do not reset Git or delete your project.
