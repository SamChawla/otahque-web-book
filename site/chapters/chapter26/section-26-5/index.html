Checkpoint: Quiz and Challenge

Quiz

Que. 3 Sam presses Publish on the clinic, which has no description and starts next week. What does the page show, what is stored, and where does the rule live?

Flip to check your answerFold answer back

Answer. The page returns to the draft with Add a description. in an error message, and the event is still a draft. The rule lives in the model: readiness_problems() returns the message and publish() raises it before changing the status, so the answer is the same whether the request comes from a button, a crafted POST, or the shell.

Que. 4 A crawler follows the links on Sam’s pages. Why does that not delete the draft, publish it, or cancel it?

Flip to check your answerFold answer back

Answer. The delete link opens a confirmation page, which only reads. Publishing and cancelling are POST-only views, so a GET to their addresses answers 405 and changes nothing. A POST also needs the CSRF token that only Otahque’s own forms carry.

Que. 5 Why does delete_draft() delete the organizer assignments first, inside transaction.atomic()?

Flip to check your answerFold answer back

Answer. Each assignment protects its event with PROTECT, so the event cannot be deleted while one remains. Deleting them first makes the event deletable, and the transaction makes the two deletes one unit: if the second fails, the first is undone.

Que. 6 Table 26.1 has no way back from cancelled. How does Sam run a cancelled event again, and what carries over?

Flip to check your answerFold answer back

Answer. He copies it to a new draft, with a new start. The title, description, place, time zone, capacity, and length carry over. Registrations, the status, and other organizers do not, and Sam becomes the new draft’s organizer.

Que. 7 You apply 0004, then run uv run python manage.py migrate events 0003. What happens to the description column and to what was typed in it, and what would you do instead on a database that holds real events?

Flip to check your answerFold answer back

Answer. The migration is unapplied: the column is dropped, and the descriptions in it are lost, as sqlmigrate events 0004 --backwards shows. On a database with real data, you would not roll back. You would fix forward with a new migration, after reading the SQL of each step with sqlmigrate.

Mini-Challenge

Que. 8 Predict what readiness_problems() returns for three drafts: A, complete and starting in seven days; B, with no description, started yesterday, with Sam as organizer; and C, with a description of three spaces, starting in seven days, and no organizer. Then check with the file below, run with uv run python manage.py shell -c "exec(open('challenge.py').read())".

Flip to check your answerFold answer back

Answer. A has no problems. B has two: Add a description. and Move the start to a time in the future. C has two: a description of spaces counts as missing, and there is no current organizer. The file rolls its work back, so your rows are unchanged:

challenge.py (practice file; delete it afterwards)

from datetime import timedelta

from django.db import transaction
from django.utils import timezone

from accounts.models import User
from events.models import Event

sam = User.objects.get(email='sam@example.org')
DRAFTS = [('A', 7, 'Bring a laptop.', True),
          ('B', -1, '', True),
          ('C', 7, '   ', False)]
with transaction.atomic():
    for title, days, description, organized in DRAFTS:
        start = timezone.now() + timedelta(days=days)
        event = Event.objects.create(
            title=title, description=description,
            timezone='Europe/London', starts_at=start,
            ends_at=start + timedelta(hours=1),
            location='Online', capacity=20,
        )
        if organized:
            event.add_organizer(sam)
        problems = event.readiness_problems()
        print(title, len(problems), 'problems')
        for problem in problems:
            print('  ' + problem)
    transaction.set_rollback(True)

Output

A 0 problems
B 2 problems
  Add a description.
  Move the start to a time in the future.
C 2 problems
  Add a description.
  Assign at least one current organizer.

What We Learned

  • An event has three states and a short list of moves; anything not on the list is refused, and each refusal changes nothing.
  • A change of state is a POST, behind a form with the CSRF token; a GET only reads, and a view that accepts only POST answers a GET with 405.
  • Readiness is stricter than validity, and it lives in the model: readiness_problems() lists what is missing, and publish() refuses until the list is empty.
  • A new text column is TextField(blank=True), with the empty string as its “no data”; sqlmigrate shows a migration’s SQL without running it, and migrate app number undoes migrations, at the cost of the data in what is dropped.
  • A protected foreign key stops a delete until the rows that point at it are gone, so a draft is deleted with its assignments, in one transaction.
  • Delete asks first, on a page that only reads, and refuses everything but a draft with no registrations; cancelling keeps the story that deleting would erase.
  • get_absolute_url() lets the model say where it lives, for redirects and for the admin.
  • One query with both conditions inside one filter(), and a test that counts queries, keep a list page honest.
  • One method, can_be_edited_by(), answers who may act; Chapter 30 will plug roles into it.
