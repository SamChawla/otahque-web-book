The Custom Way

Without the rules of this chapter, an event’s views delete when their address is opened. This illustration, plain Python with no Django, shows what a crawler does to each style. Run it with any Python, and do not add it to the project:

illustration_only/by_link.py (not part of the project)

START = {6: 'Online Django clinic', 7: 'Python meetup'}
LINKS = ['/events/6/delete/', '/events/7/delete/']


def by_link(events, path, method):
    """Delete whenever the address is opened."""
    events.pop(int(path.split('/')[2]), None)


def by_form(events, path, method):
    """Delete only for a POST; refuse anything else."""
    if method != 'POST':
        return 405
    events.pop(int(path.split('/')[2]), None)


def crawl(handler):
    """Act as a crawler: open every link with a GET."""
    events = dict(START)
    for link in LINKS:
        handler(events, link, 'GET')
    return events


print('by link:', crawl(by_link))
print('by form:', crawl(by_form))

Output

by link: {}
by form: {6: 'Online Django clinic', 7: 'Python meetup'}

A crawler opens every address it finds with a GET. The first handler treats the address itself as the instruction, so the crawl emptied the list. The second accepts only a POST, so the same crawl changed nothing. The rest of the chapter builds the second kind, for an event’s whole life.

The Django Way

Django gives each piece a place. The model holds the rules: what is missing, which moves are allowed, and the deletion in one transaction. A decorator, require_POST, answers anything but a POST with 405. A shared function decides who may act. Templates show buttons only to the people who may use them, and the views still refuse everyone else.

# Event states: low-level design

Status: Drafted in Chapter 26, for review. Not approved.
Who may act: current organizers who hold events.change_event
(Event.can_be_edited_by, Chapter 25). Chapter 30 replaces
the rule behind that one method with roles.

## States and moves

- publish: draft to published. Refused when it is not a
  draft, has no description, does not start in the future,
  or has no current organizer.
- cancel: published to cancelled. Refused when not published.
- delete: a draft is removed. Refused when it is not a draft,
  or when any registration exists.
- copy: any state to a new draft. Refused when the new start
  is missing or unreadable.

- There is no unpublish. Cancelled is final: run the event
  again by copying it.
- Every move except the delete page's GET is a POST. The
  views for publish and cancel answer a GET with 405.
- A refused move changes nothing and tells the member why
  (one message per missing detail).

## What each state shows

- Draft: organizers and view_event holders; a Draft banner.
- Published: everyone; in the upcoming and past lists.
- Cancelled: everyone who has the address, with a
  Cancelled tag and no places line; not in either list.
  Registrations stay as they are.

## Request path

- POST events/<id>/publish/ and .../cancel/: require_POST,
  login_required, event_to_manage (404 hidden, 403
  refused), then event.publish() or event.cancel();
  ValidationError messages become error messages; 302 to
  the event.
- GET events/<id>/delete/: the confirmation page (a draft
  only). POST: event.delete_draft() removes the draft's
  organizer assignments, then the event, in one
  transaction; 302 to My events.
- GET/POST events/<id>/copy/: asks for the new start in the
  event's zone; event.copy_as_draft(user, starts_at) copies
  title, description, place, time zone, capacity, and
  length; never registrations, status, or other organizers;
  302 to the new draft's edit page.
- GET events/manage/: permission_required(change_event);
  Event.objects.organized_by(user): current assignments
  only, drafts first.
