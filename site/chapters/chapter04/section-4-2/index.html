4.2 Collections and loops

Sam now has more than one event to describe. Giving every title a separate variable would make the same display task increasingly awkward. A collection groups values so that one piece of code can work through them. We will start with titles, add the details of one event, and then bring those ideas together.

Continue from the paper trace in 4.1. You need its assignment, Boolean, and indentation ideas, but no installed tools, working directory, files, or application checkpoint. Your output is an annotated event-list trace and predictions for changed inputs. Saving and running a file comes in 4.5. All event details here are fictional practice data.

A list keeps items in order

A list is an ordered collection of items. Square brackets enclose the list, and commas separate its items. Here the items are strings:

titles = ["Python Evening", "Testing Clinic"]
print(titles[0])
print(len(titles))

Expected output:

Python Evening
2

An index identifies a position. Python starts list indexes at zero, so titles[0] selects the first item and titles[1] selects the second. The built-in len function gives the number of items. A length of 2 does not make 2 a valid positive index: these two positions are 0 and 1.

Que. 6 What happens if this example reads titles[2]?

Show answerHide answer

Answer. Python raises IndexError because that position does not exist. It does not return an empty string. Count the items and check the index before changing the example; do not add a made-up event just to hide the mistake. Section 4.4 will explain how to read error messages.

A dictionary gives each detail a key

One event has several related details. A dictionary associates keys with values. In this example, the keys are the strings "title" and "is_published". Curly braces enclose the dictionary; a colon separates each key from its value, and commas separate the pairs.

event = {
    "title": "Python Evening",
    "is_published": True,
}
print(event["title"])
print(event["is_published"])

Expected output is Python Evening, then True, on separate lines. The trailing comma after the final pair is allowed. Splitting the dictionary across lines makes its details easier to read; it is still one assignment.

The brackets after event perform a lookup. Unlike a list index, "title" names a key rather than a position. The key "is_published" is text; its associated value True is a Boolean. A key and its value do different jobs, even when they appear together.

Que. 7 Are event["title"] and event["Title"] interchangeable?

Show answerHide answer

Answer. No. These are different string keys. This dictionary contains "title", so looking up "Title" raises KeyError. Check the spelling and capitalization against the supplied data. Also, event[0] would look for the key 0; it would not mean “the first detail”.

Repeat a task with a for loop

A loop repeats a block of code. A for loop takes each item from a collection in turn. Each pass through the block is an iteration. This separate example uses the two titles again:

titles = ["Python Evening", "Testing Clinic"]
for title in titles:
    print(title)
print("Finished")

Read the for line as “for each item in titles, bind title to that item and run the indented block”. The singular name title is our choice, not special Python syntax. On the first pass it refers to "Python Evening"; on the second it refers to "Testing Clinic".

Expected output:

Python Evening
Testing Clinic
Finished

The final print lines up with for, so it runs once after the loop. Moving it four spaces to the right would put it inside the loop and print Finished after each title. Indentation determines which work repeats. This loop reads the list without changing it.

Que. 8 What changes if titles is an empty list, written []?

Show answerHide answer

Answer. There are no items, so the loop body runs zero times. The final print still runs and displays Finished. An empty collection is a valid input to a for loop; the loop does not invent a first item.

Combine a list, dictionaries, and a decision

We can put dictionaries inside a list. The outer list groups events; each dictionary groups the details of one event. This is a small in-memory representation for learning, not a database model or saved application data. Read this complete example from the assignment onward:

events = [
    {"title": "Python Evening", "is_published": True},
    {"title": "Testing Clinic", "is_published": False},
]

for event in events:
    if event["is_published"]:
        print(event["title"])
print("Review complete")

The two kinds of lookup are separated in Figure 4.2. events[0] selects a dictionary by its position in the list. Adding ["title"] selects the title from that dictionary. In the loop, event already refers to the current dictionary, so we use event["title"] directly.

The if line sits four spaces inside for. Its print sits eight spaces in, inside both blocks. There is no else: when the supplied Boolean is False, the body of if is skipped and the loop continues with its next item, if any. The last print is outside both blocks.

A dash in the last column means that no title is printed on that pass. Expected output:

Python Evening
Review complete

This trace selects a display message from supplied data. It neither publishes an event nor proves that a visitor may access it. Later server-side code must enforce the real visibility rules. We also keep the collection unchanged during iteration; adding or removing its items while traversing it needs separate care.

Que. 9 Does for event in events loop over dictionary keys?

Show answerHide answer

Answer. No. Here events is a list, so each item supplied to the loop is a whole dictionary. A loop directly over a dictionary would yield its keys. Check the collection after in before deciding what the loop variable represents.

In practice: checking a collection with no results

Situation. A future event list has no published events to show, although the code was first tried with several examples.

Application. Use the empty-list case to reason about what a loop does when it has no items. Decide what the surrounding program should do after that loop.

Consideration. Do not assume there is always a first item to read. The chapter’s in-memory collection is practice data, not a saved event database.

Try it yourself

Trace the complete events example three times on paper. First, change the second is_published value to True. Second, make both values False. Third, replace the entire list assignment with events = []. For each case, write the exact output and the number of loop-body executions. Keep the final print outside the loop.

Que. 10 What should the three traces show?

Show answerHide answer

Answer. With both values True, the output is Python Evening, Testing Clinic, and Review complete on three lines; the loop body runs twice. With both values False, only Review complete appears, but the loop body still runs twice and checks both conditions. With events = [], only Review complete appears and the loop body runs zero times. No printed titles can therefore mean either an empty list or a non-empty list with no matching events.

Check your readiness

You are ready for the next section when you can distinguish a list position from a dictionary key and explain which lines run for every item. If your trace differs, draw the list positions, write the current dictionary beside each pass, and mark the indentation levels. Keep your first prediction so that you can identify the assumption you corrected. Revisit the empty case as well as the two-event case.
