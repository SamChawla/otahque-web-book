What You Need to Know

New Concept: the Python readiness bridge

What problem exists? Django examples combine Python values, collections, functions, and objects. A gap in one of these can make an otherwise small example difficult to follow.

What did people do before? A reader might copy a complete example and inspect it only after an error. Here we first predict what a smaller example does.

What is the bridge? A review of prerequisite Python through four groups: values and decisions, collections and loops, functions and imports, and classes and errors.

Why review them together? Their results connect: a collection supplies a value to a function, and an object keeps related values and behaviour together.

Now let’s trace the examples on paper, compare the answers, and later run saved versions in How We Build It.

Values, names, and decisions

Sam prepares an event for Otahque. He needs a private draft before visitors can read the published event. The product requirements distinguish those two states. How can a small Python example represent that distinction and choose an appropriate message?

For this section, read and trace the examples on paper. No installation, file, shell command, or existing application checkpoint is required. The examples use invented values and do not connect to Otahque. How We Build It will show how to save and run a Python file. Your visible result now is a prediction you can compare with each worked answer.

Give a value a meaningful name

A value is a piece of data, such as the event title or a number. A variable name lets a program refer to a value. Read the following lines from top to bottom:

Python

event_title = "Python Evening"
capacity = 12
is_published = False

Each line is an assignment. The equals sign binds the name on its left to the value on its right. Here, event_title refers to text, capacity refers to a whole number, and is_published refers to a yes-or-no value. The underscores make multiword names readable without spaces.

Text is called a string; the quotation marks delimit it in the source code. A whole number is an integer. A Boolean is one of the two values True and False, written with those capital letters and without quotes. These kinds of values are called types. The type matters when we ask Python to calculate or compare.

The invented capacity of 12 is practice data, not a selected limit for Otahque. Likewise, the name is_published helps explain our intent but cannot enforce the publication rules by itself.

Que. 1 Are False and "False" the same value?

Flip to check your answerFold answer back

Answer. No. False is a Boolean; "False" is a string containing five letters. Quotation marks change how Python interprets the value. Use the Boolean when the example needs an actual yes-or-no fact, rather than text that happens to spell its name.

Separate assigning from comparing

An expression is code that produces a value. For example, capacity - 1 produces the number one below capacity. A comparison asks a question and produces True or False. Python uses == to ask whether two values are equal; a single = performs assignment.

Python

capacity = 12
print(capacity == 12)
print(capacity == 8)

print is a built-in function: a named operation Python already provides. The parentheses contain what we ask it to display. Here Python evaluates each comparison first, then prints its result. Expected output, on two separate lines:

Output

True
False

A program printing True has answered this one comparison. It has not proved that an event is valid, that Sam may manage it, or that registration is open. Those are separate product questions. Keeping each question precise will matter when we later translate the PRD into checks.

Que. 2 What is the difference between capacity = 12 and capacity == 12?

Flip to check your answerFold answer back

Answer. The first binds capacity to 12. The second compares its current value with 12 and produces a Boolean result. A comparison does not change capacity.

Common Error: = where you meant ==

A single equals sign assigns; a double equals sign compares. Writing if capacity = 12: is a SyntaxError, because an if needs a question, not an assignment. When a condition fails to parse, check each comparison for a missing second =.

Follow one branch

A condition is an expression used to choose what happens next. In this example, the condition is the Boolean value named is_published. The if statement selects the first indented block when that value is True; otherwise, else selects the second block.

Python

is_published = False

if is_published:
    print("Public event")
else:
    print("Private draft")

The colon introduces a block. The four spaces before each print show that it belongs inside that branch. Indentation is part of Python’s structure, not decoration. The if and else lines line up; their contents sit one indentation level further in.

Start with the assigned value: False. Follow the else branch. The expected output is Private draft. Only one of these two messages is printed. Figure 4.1 shows that choice; neither path changes is_published.

Now change only the first line to is_published = True. The condition selects the first branch and the output becomes Public event. This is a useful way to check your understanding: vary one input and explain which path changes before looking at the answer.

Que. 3 Does printing Public event publish an Otahque event?

Flip to check your answerFold answer back

Answer. No. This example only displays text. It does not store an event, check Sam’s assignment, or make a page public. The real publication workflow must enforce those requirements on the server. A small Python branch is a language exercise, not a completed feature.

Trace a change instead of guessing

Assignment uses the values available when that line executes. It does not create a live formula that automatically follows later changes. Consider this separate arithmetic example, with fictional counts:

Python

capacity = 12
active_count = 9
remaining = capacity - active_count
active_count = 10
print(remaining)

Trace the names after each step. A dash in Table 4.1 means that this example has not assigned that name yet; it is not a Python value.

The output is 3. To obtain 2 after the count changes, calculate remaining = capacity - active_count again after active_count = 10. The earlier result does not update itself. This explains a language rule; it is not a safe algorithm for allocating a real event’s final place. Shared records and overlapping requests need the later database and transaction lessons.

In practice: naming a decision clearly

Situation. A developer returns to an event-visibility condition several weeks after writing it.

Application. A name such as is_published helps them connect the Boolean value to the decision it controls. Checking both values exposes which branch supplies each result.

Consideration. A clear name is useful documentation, not enforcement. A visibility example still needs the application’s actual access rules before it can protect private data.

Try it yourself

Use the two examples above without running them. First, write the message produced by the branch when is_published is False, then when it is True. Second, in the arithmetic example, change only active_count = 10 to active_count = 12. Predict the printed result before and after adding a fresh calculation of remaining just before print. Explain every result in one sentence.

Que. 4 What should the predictions and explanations say?

Flip to check your answerFold answer back

Answer. False selects else and prints Private draft; True selects if and prints Public event. Changing active_count to 12 still leaves the earlier remaining value at 3, so the unchanged print displays 3. Recalculating just before printing subtracts 12 from 12 and displays 0. A new assignment changes a name’s value; an earlier calculation is not automatically repeated.

Decide what to practise next

If you can explain the branch and trace the changed values, continue to collections and loops. If you guessed, cover the answers and write the value of each name after every line. For a branch, underline the supplied condition and mark only the block it selects. Compare your trace with the worked results, then change one input and try again.

Common gaps are treating quoted text as a Boolean, using = when asking an equality question, ignoring indentation, or expecting a calculation to refresh itself. Practise the specific gap with another tiny example before adding Django syntax. You do not need to memorize every Python feature to proceed, but you should be able to explain these results in your own words.

Que. 5 Why predict a result before running the program?

Flip to check your answerFold answer back

Answer. The prediction makes your understanding visible. If the observed result later differs, you have a specific assumption to investigate. A successful run alone cannot tell you whether you understand the branch or whether the example satisfies the product requirements.

Further practice: for more examples of these ideas, the official Python 3.14 tutorial covers them in Numbers, Text, and if Statements. Try their short examples, then return here; you do not need the rest of the tutorial yet.

Collections and loops

Sam now has more than one event to describe. Giving every title a separate variable would make the same display task increasingly awkward. A collection groups values so that one piece of code can work through them. We will start with titles, add the details of one event, and then bring those ideas together.

Continue from the paper trace above. You need its assignment, Boolean, and indentation ideas, but no installed tools, working directory, files, or application checkpoint. Your output is an annotated event-list trace and predictions for changed inputs. Saving and running a file comes in How We Build It. All event details here are fictional practice data.

A list keeps items in order

A list is an ordered collection of items. Square brackets enclose the list, and commas separate its items. Here the items are strings:

Python

titles = ["Python Evening", "Testing Clinic"]
print(titles[0])
print(len(titles))

Expected output:

Output

Python Evening
2

An index identifies a position. Python starts list indexes at zero, so titles[0] selects the first item and titles[1] selects the second. The built-in len function gives the number of items. A length of 2 does not make 2 a valid positive index: these two positions are 0 and 1.

Que. 6 What happens if this example reads titles[2]?

Flip to check your answerFold answer back

Answer. Python raises IndexError because that position does not exist. It does not return an empty string. Count the items and check the index before changing the example; do not add a made-up event just to hide the mistake. Reading error messages comes at the end of this part.

A dictionary gives each detail a key

One event has several related details. A dictionary associates keys with values. In this example, the keys are the strings "title" and "is_published". Curly braces enclose the dictionary; a colon separates each key from its value, and commas separate the pairs.

Python

event = {
    "title": "Python Evening",
    "is_published": True,
}
print(event["title"])
print(event["is_published"])

Expected output is Python Evening, then True, on separate lines. The trailing comma after the final pair is allowed. Splitting the dictionary across lines makes its details easier to read; it is still one assignment.

The brackets after event perform a lookup. Unlike a list index, "title" names a key rather than a position. The key "is_published" is text; its associated value True is a Boolean. A key and its value do different jobs, even when they appear together.

Que. 7 Are event["title"] and event["Title"] interchangeable?

Flip to check your answerFold answer back

Answer. No. These are different string keys. This dictionary contains "title", so looking up "Title" raises KeyError. Check the spelling and capitalization against the supplied data. Also, event[0] would look for the key 0; it would not mean “the first detail”.

Repeat a task with a for loop

A loop repeats a block of code. A for loop takes each item from a collection in turn. Each pass through the block is an iteration. This separate example uses the two titles again:

Python

titles = ["Python Evening", "Testing Clinic"]
for title in titles:
    print(title)
print("Finished")

Read the for line as “for each item in titles, bind title to that item and run the indented block”. The singular name title is our choice, not special Python syntax. On the first pass it refers to "Python Evening"; on the second it refers to "Testing Clinic".

Expected output:

Output

Python Evening
Testing Clinic
Finished

The final print lines up with for, so it runs once after the loop. Moving it four spaces to the right would put it inside the loop and print Finished after each title. Indentation determines which work repeats. This loop reads the list without changing it.

Que. 8 What changes if titles is an empty list, written []?

Flip to check your answerFold answer back

Answer. There are no items, so the loop body runs zero times. The final print still runs and displays Finished. An empty collection is a valid input to a for loop; the loop does not invent a first item.

Combine a list, dictionaries, and a decision

We can put dictionaries inside a list. The outer list groups events; each dictionary groups the details of one event. This is a small in-memory representation for learning, not a database model or saved application data. Read this complete example from the assignment onward:

Python

events = [
    {"title": "Python Evening", "is_published": True},
    {"title": "Testing Clinic", "is_published": False},
]

for event in events:
    if event["is_published"]:
        print(event["title"])
print("Review complete")

The two kinds of lookup are separated in Figure 4.2. events[0] selects a dictionary by its position in the list. Adding ["title"] selects the title from that dictionary. In the loop, event already refers to the current dictionary, so we use event["title"] directly.

The if line sits four spaces inside for. Its print sits eight spaces in, inside both blocks. There is no else: when the supplied Boolean is False, the body of if is skipped and the loop continues with its next item, if any. The last print is outside both blocks.

A dash in the last column means that no title is printed on that pass. Expected output:

Output

Python Evening
Review complete

This trace selects a display message from supplied data. It neither publishes an event nor proves that a visitor may access it. Later server-side code must enforce the real visibility rules. We also keep the collection unchanged during iteration; adding or removing its items while traversing it needs separate care.

Que. 9 Does for event in events loop over dictionary keys?

Flip to check your answerFold answer back

Answer. No. Here events is a list, so each item supplied to the loop is a whole dictionary. A loop directly over a dictionary would yield its keys. Check the collection after in before deciding what the loop variable represents.

In practice: checking a collection with no results

Situation. A future event list has no published events to show, although the code was first tried with several examples.

Application. Use the empty-list case to reason about what a loop does when it has no items. Decide what the surrounding program should do after that loop.

Consideration. Do not assume there is always a first item to read. The chapter’s in-memory collection is practice data, not a saved event database.

Try it yourself

Trace the complete events example three times on paper. First, change the second is_published value to True. Second, make both values False. Third, replace the entire list assignment with events = []. For each case, write the exact output and the number of loop-body executions. Keep the final print outside the loop.

Que. 10 What should the three traces show?

Flip to check your answerFold answer back

Answer. With both values True, the output is Python Evening, Testing Clinic, and Review complete on three lines; the loop body runs twice. With both values False, only Review complete appears, but the loop body still runs twice and checks both conditions. With events = [], only Review complete appears and the loop body runs zero times. No printed titles can therefore mean either an empty list or a non-empty list with no matching events.

Check your readiness

You are ready for the next section when you can distinguish a list position from a dictionary key and explain which lines run for every item. If your trace differs, draw the list positions, write the current dictionary beside each pass, and mark the indentation levels. Keep your first prediction so that you can identify the assumption you corrected. Revisit the empty case as well as the two-event case.

Further practice: for more examples of these ideas, the official Python 3.14 tutorial covers them in More on Lists, Dictionaries, and for Statements. Try their short examples, then return here; you do not need the rest of the tutorial yet.

Functions and imports

Sam wants the same event-label rule in more than one place. Copying a branch each time creates several places to correct when the rule changes. A function gives that small task a name and lets another part of the program ask for its result.

Continue tracing on paper. No installation or application checkpoint is needed yet. This section produces a call trace and a two-file sketch; How We Build It supplies the saving and running steps. The example chooses text from supplied practice values, not access to a real event.

Define a task, then call it

Python

def event_label(title, is_published):
    if is_published:
        return title
    return "Private draft"

The keyword def begins a function definition. event_label is the function name. The names title and is_published inside its parentheses are parameters: local names for values supplied when the function is called. The colon and indented body have the same structural role you met with if and for.

Executing this definition makes the function available; it does not yet run the branch or print anything. A call uses parentheses after the function name. The supplied values are arguments. Read this after the definition above:

Python

message = event_label("Python Evening", True)
print(message)

The first argument becomes the local title and the second becomes the local is_published. The True branch reaches return title. return ends this call and supplies its result to the caller, the code that made the call. The assignment binds message to "Python Evening"; only the following print displays it. With False, execution skips that branch and reaches return "Private draft".

Que. 11 What happens to the second return when is_published is True?

Flip to check your answerFold answer back

Answer. It is not reached during that call. The first return ends the function call. A later call starts a new execution of the body with its own supplied arguments.

Returning and printing do different jobs

A returned value can be stored, compared, or passed to another operation. Printing sends a textual representation to the output destination. It does not give the printed text back as the result of your function. Compare this deliberately different function:

Python

def show_title(title):
    print(title)

result = show_title("Python Evening")
print(result)

Expected output:

Output

Python Evening
None

show_title prints the first line. It then reaches the end without a return value, so its call returns None, Python’s value for the absence of a result here. The outer print displays that value. None is neither the empty string nor the string "None". Use event_label when a caller needs the text as data; printing can remain the caller’s choice.

Que. 12 Would assigning a call to a variable prevent its internal print?

Flip to check your answerFold answer back

Answer. No. result = show_title(...) still executes the function body, including print. Assignment stores the returned value; it does not cancel other work performed during the call.

Keep track of local names

Scope is the region in which a name can be looked up. A function’s parameters and ordinary assignments inside it are local to that call. The following separate example has two names spelled title:

Python

title = "Python Evening"

def replace_title(title):
    title = "Private draft"
    return title

print(replace_title(title))
print(title)

The output is Private draft, then Python Evening. Reassigning the local parameter does not reassign the caller’s title. This does not mean that Python copies every argument: a function can change a supplied list or dictionary if it performs a modifying operation on that object. Our label function only reads its arguments.

Que. 13 Can the caller read a function’s local variable by using its name after the call?

Flip to check your answerFold answer back

Answer. Not merely because the function created it. A local name is not automatically added to the caller’s scope. Return the value that the caller needs and assign that result there. If no binding for a name can be found, Python raises NameError.

Put reusable definitions in a module

For our purposes, a module is a Python file containing definitions and statements. Sketch two files in the same directory. event_text.py contains only the event_label definition shown above. preview.py contains the following complete runner:

Python

from event_text import event_label

print(event_label("Python Evening", True))
print(event_label("Testing Clinic", False))

from event_text import event_label makes that function name available in preview.py. The module name omits the .py ending. These two calls print Python Evening and Private draft, on separate lines. A second spelling is import event_text followed by event_text.event_label(...); the dot accesses the function through the module name. Do not mix the two spellings without understanding which names the import introduced.

An import can execute a module’s top-level statements when the module is first loaded in that interpreter. Our reusable module contains only a definition, so importing it does not print an event. Keep demonstration calls in preview.py. Imports make available code usable; they do not install a missing package.

Under the Hood: how import finds a module

from event_text import event_label asks Python to find a module named event_text. Python first checks sys.modules, the modules already loaded in this run. Otherwise it searches the directories listed in sys.path in order; the first entry is normally the directory of the script you ran, which is why preview.py finds event_text.py beside it. The first match wins, so a local file named after a library module, such as json.py, hides the real one. A module is executed once per run, when it is first imported, and the loaded module is reused after that.

That search order has a practical side when two files need the same code.

In practice: sharing a small piece of behaviour

Situation. Two parts of a project need the same event-label wording, and separately copied versions begin to differ.

Application. Put the shared operation in a function and import it where needed. Returning the label lets each caller decide how to use the result.

Consideration. Only share behaviour that really has the same meaning. Importing a module should not unexpectedly run its demonstration program.

Flip to check your answerFold answer back

Answer. Both event_label calls would return Private draft, so the runner would print that text twice. A top-level print("Loaded") in event_text.py would execute when the import first loads that module and print Loaded before the two calls. Classes and reading errors

Soni compares two event cards. Each has its own title, but both can produce a label in the same way. A class can describe that shared behaviour while each instance holds its own data. We need enough of this vocabulary to read later Django examples, without designing a database model yet.

Start from the functions and calls above. This section remains a paper exercise: explain two instances and diagnose a short failure. The named files are sketches that you can save and run in How We Build It. No application or database exists at this checkpoint.

Read a class one part at a time

Sketch event_card.py with this complete definition:

Python

class EventCard:
    def __init__(self, title):
        self.title = title

    def label(self):
        return "Event: " + self.title

class EventCard defines a new kind of object. An instance is one object created from that class. Calling EventCard("Python Evening") makes an instance and initializes it using __init__. The name __init__ has two underscores at each end; it is a special initialization method recognized by Python.

A method is a function associated with a class. self is the conventional name for the instance supplied to an instance method. In self.title = title, the right-hand title is the argument’s local name; self.title is an attribute, a named value attached to this instance. The dot selects that attribute. label reads it and uses + to join two strings.

Sketch class_demo.py beside event_card.py:

Python

from event_card import EventCard

first = EventCard("Python Evening")
second = EventCard("Testing Clinic")
first.title = "Python Afternoon"
print(first.label())
print(second.label())

Expected output:

Output

Event: Python Afternoon
Event: Testing Clinic

first and second refer to separate instances. Changing first.title in this example changes only first’s title attribute. When first.label() is called, Python supplies first as self; we do not pass it again. The method returns the assembled string, and the surrounding print displays it.

Que. 15 Why does label(self) have a parameter when first.label() has no argument inside the parentheses?

Flip to check your answerFold answer back

Answer. Calling this instance method through first supplies that instance automatically as self. Other parameters, if the method defined any, would need their own arguments. self is a convention for this role, not the name of a global event.

Recognize inheritance without designing around it

A class can build on another class. This is inheritance. After importing EventCard, the following small example defines a subclass named PreviewCard; EventCard is its base class. pass means “no statement to perform here” and provides the required body:

Python

from event_card import EventCard

class PreviewCard(EventCard):
    pass

card = PreviewCard("Python Evening")
print(card.label())

The output is Event: Python Evening. PreviewCard has not replaced the inherited initialization or label method, so those behaviours are available through it. The name PreviewCard does not enforce privacy. Later Django classes will use inheritance for concrete purposes; this example teaches how to recognize the parentheses after a class name.

Separate three kinds of mistake

An error message is evidence about an execution, not a judgement about your ability. Begin by deciding whether Python could read the program, whether an operation failed while it ran, or whether it ran but gave an incorrect result.

SyntaxError means Python could not parse the code. IndentationError is a syntax-related error. An exception raised during execution may be KeyError, NameError, TypeError, or another specific type. A logic mistake may raise no exception at all, which is why our changed-input predictions matter.

Read a traceback from the failure back to its caller

This deliberately failing sketch is error_demo.py. Count its blank lines too when locating line numbers:

Python

def read_title(event):
    return event["title"]


sample = {"name": "Python Evening"}
print(read_title(sample))

The relevant traceback is shown below with the directory part of each filename and any caret markers omitted. Those display details can vary. The exception type and the two call locations are the evidence to follow:

Output

Traceback (most recent call last):
  File "error_demo.py", line 6, in <module>
    print(read_title(sample))
  File "error_demo.py", line 2, in read_title
    return event["title"]
KeyError: 'title'

Read the final line first: the key "title" was not found. The frame immediately above it locates the lookup in read_title. A frame identifies one step in the chain of calls; the earlier frame shows which call supplied sample. Inspect sample: it has the key "name", while this function expects "title". Python cannot infer that those words were meant to refer to the same detail.

For this exercise, the agreed input shape uses "title". Correct the sample key in a separate copy of the file, keeping the original as evidence. Running the corrected copy should print Python Evening. Changing unrelated code or catching every exception and printing “success” would obscure the cause.

Flip to check your answerFold answer back

Answer. It shows where this exception was raised, which is a useful starting point. Here the failed lookup is in the function, but the mismatched input was created by its caller. Follow the values through the call chain before deciding what to change.

In practice: handing over a reproducible failure

Situation. A small Python program fails for a particular input, and another developer needs to investigate.

Application. Keep the exception type, relevant traceback lines, and a minimal example of the input. Trace the value from its caller to the failing operation before changing code.

Consideration. Remove private data before sharing the example. The line where an exception appears may be downstream from the mistake that supplied the value.
