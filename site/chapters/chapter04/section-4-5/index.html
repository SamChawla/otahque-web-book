Checkpoint: Quiz and Challenge

Quiz

Que. 23 What does titles[0] select, and why is titles[1] not the first item?

Flip to check your answerFold answer back

Answer. The first item: Python counts list positions from zero, so titles[1] is the second item.

Que. 24 What is the difference between a parameter and an argument?

Flip to check your answerFold answer back

Answer. A parameter is the local name in the function definition, such as title; an argument is the value supplied by a call, such as "Python Evening".

Que. 25 In first.label(), what does self refer to inside label?

Flip to check your answerFold answer back

Answer. The instance first. Python supplies it automatically as the first argument of an instance method.

Que. 26 Which line of a traceback should you read first, and why?

Flip to check your answerFold answer back

Answer. The last line, which names the exception and its message. Then read the frames above it to see which calls led there.

Que. 27 check_environment.py prints True on its last line. What does that tell you, and what does it not?

Flip to check your answerFold answer back

Answer. That the running interpreter is inside a virtual environment, because its prefix differs from the base prefix. It does not show which environment, which is why the executable path matters, and it says nothing about whether any program is correct.

Mini-Challenge

Add a function to readiness_changed.py named published_titles(events) that returns a list of the published titles, in order. Use a for loop, an if, and the list method append, which adds an item to the end of a list. Add two assertions: one for the two-event list and one for the empty list. Run the file with the same environment.

Que. 28 What would a working answer look like?

Flip to check your answerFold answer back

Answer. For example:

readiness_changed.py (added lines)

def published_titles(events):
    titles = []
    for event in events:
        if event["is_published"]:
            titles.append(event["title"])
    return titles


assert published_titles(events) == ["Python Evening"]
assert published_titles([]) == []

The return sits outside the loop, so every event is considered. The empty list returns an empty list rather than None. With the original two events, the run still ends with Readiness checks passed.

What We Learned

  • Assignment binds a name to a value, and comparison asks a question; an if runs only the branch its condition selects.
  • Lists select by position from zero, dictionaries by key, and a for loop runs its body once per item, including zero times for an empty list.
  • A function returns a value to its caller; printing displays text but returns None.
  • A class defines shared behaviour, and each instance keeps its own attributes; self is the instance a method was called on.
  • Read a traceback from its last line, then follow the values back through the calls.
  • uv pins Python 3.14.9 and creates .venv; naming --python .venv in commands makes the interpreter you ran visible and checkable.

Readiness checkpoint: Before moving into Django setup, explain a branch and a loop including the empty case; distinguish return from print; follow a module import and an instance-method call; and locate a failing operation in a traceback. On your own machine, record the uv and Python versions, current practice-directory path, expected and actual preview output, environment identity result, uv package-list result, and readiness result. Keep those observations in a plain-text file named readiness-notes.txt in the practice directory. Use your actual paths and results; there is no pre-filled claim of success.

If a language prediction is uncertain, return to that section’s short exercise. If a command fails, preserve the error and use the directory/interpreter checks before changing code. Completing only the paper work is useful progress, but the tools checkpoint is complete only after you run and explain the results on your machine. This chapter has prepared Python practice files, not a Django application or a verified registration feature.

There is nothing to commit. The practice folder is a workspace for this chapter, not the Otahque project, and Git arrives with the project in Chapter 8. Keep readiness-notes.txt as your own record.
