Checkpoint: Quiz and Challenge

Quiz

Que. 3 Why does Otahque’s sign-out button sit inside a form, and what happens if a page links to /accounts/logout/ instead?

Flip to check your answerFold answer back

Answer. Signing out changes the session, so it is a POST with the CSRF token, by Chapter 26’s rule. A link sends a GET, and allauth answers a GET with a page that asks for confirmation; the member stays signed in until that page’s button sends the POST.

Que. 4 Sai signs up as SAI@Example.ORG. What is stored, and which two places make sure of it?

Flip to check your answerFold answer back

Answer. sai@example.org. Chapter 21’s model rule lower-cases the email when a member is saved, and its database constraint refuses a capital letter from anywhere; allauth’s sign-up goes through both.

Que. 5 Where does Otahque refuse raj@mailinator.com, and what would you change to accept a domain the list names by mistake?

Flip to check your answerFold answer back

Answer. In AccountAdapter.clean_email(), which allauth calls with every address at sign-up, after Django’s own check. Add the domain to DJANGO_EMAIL_DOMAINS_ALLOWED in .env, which EMAIL_DOMAINS_ALLOWED reads.

Que. 6 Sam has an account with a password. He chooses GitHub on the sign-in page, and GitHub confirms the same address. What happens, and why?

Flip to check your answerFold answer back

Answer. The page says that an account already exists with this email address and asks him to sign in to that account first, then connect GitHub. A provider vouches for an email, not for an Otahque account, so nothing is linked by email alone.

Que. 7 Why can the profile page not be used to change another member’s name?

Flip to check your answerFold answer back

Answer. It reads no id from the address. It edits request.user, the member who signed in, and its form ignores every field it does not list.

Mini-Challenge

Que. 8 Predict what the sign-up page does with two submissions of the same details, SAI@Example.ORG with a strong password: the first with the display name empty, the second with the display name Sai. Then check with l2_signup.py below, run with uv run python manage.py shell -c "exec(open('l2_signup.py').read())".

Flip to check your answerFold answer back

Answer. The first returns the page with status 200 and “This field is required.” for the display name, and saves nothing. The second creates the member, stored as sai@example.org with the name Sai. The file undoes its work, so your rows are unchanged:

l2_signup.py (practice file; delete it afterwards)

from django.db import transaction
from django.test import Client
from django.test.utils import setup_test_environment

from accounts.models import User

setup_test_environment()
SENT = {'email': 'SAI@Example.ORG', 'display_name': '',
        'timezone': '', 'password1': 'a-long-safe-pass-123',
        'password2': 'a-long-safe-pass-123'}
with transaction.atomic():
    web = Client()
    page = web.post('/accounts/signup/', SENT)
    form = page.context['form']
    errors = list(form.errors['display_name'])
    print('without a name:', page.status_code, errors)
    named = SENT | {'display_name': 'Sai'}
    web.post('/accounts/signup/', named)
    sai = User.objects.get(display_name='Sai')
    print('with a name:', sai.email, sai.display_name)
    transaction.set_rollback(True)

Output

without a name: 200 ['This field is required.']
with a name: sai@example.org Sai

What We Learned

  • Authentication answers who someone is; signing in records it in the session with a new key, and signing out is a POST.
  • django-allauth provides account pages and rules; it is pinned to an exact version and recorded in an ADR, and configured for Otahque’s email-only user with three settings.
  • Extra details at sign-up come from a form named in ACCOUNT_SIGNUP_FORM_CLASS; its signup() runs once the account exists.
  • A Profile holds a member’s own settings, made the first time it is needed; a page that edits request.user cannot reach another member.
  • Invalid addresses fail Django’s check; disposable ones fail the adapter’s clean_email(), against a maintained list.
  • Provider credentials live in .env; a provider’s email is never enough to link an existing account.
  • Overriding a package’s templates in templates/ keeps the package and changes its look.
  • A test can stand in for a provider by building its answer, so the suite runs offline.
