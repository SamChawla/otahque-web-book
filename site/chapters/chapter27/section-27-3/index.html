How We Build It

Start from Chapter 26, in the folder containing manage.py, with your own .env, the locked environment, 165 passing tests, every migration applied, the Node.js packages from Chapter 14, and Sam’s superuser password from Chapter 18. Step 3 downloads packages, so you need an internet connection once. The new files are accounts/forms.py, accounts/adapter.py, accounts/urls.py, accounts/templates/accounts/profile.html, accounts/migrations/0003_profile.py, four templates under templates/allauth/, docs/adr/ADR-003-accounts-allauth.md, and docs/design/sign-in.md. The commands are written the same for Windows PowerShell, Git Bash, macOS, Linux, and WSL; the chapter’s checks ran in the first two. Each step with new behaviour writes its tests first and runs them to see them fail.

The Custom Way

Django has its own sign-in and sign-out views, and a sign-in page takes three lines of URL configuration. This illustration is not part of the project:

illustration_only/urls.py (not part of the project)

from django.contrib.auth import views as auth_views
from django.urls import path

urlpatterns = [
    path('login/', auth_views.LoginView.as_view(),
         name='login'),
    path('logout/', auth_views.LogoutView.as_view(),
         name='logout'),
]

That much works, and R3’s Django for Beginners builds its sign-up the same way, with a form based on Django’s UserCreationForm. Then the list grows: a sign-up form for the custom user, a confirmation email and its link, limits on failed sign-ins, email addresses a member can change, providers, and later two-factor sign-in. Each is a new view, form, template, and set of tests, and each is a new chance to get a security detail wrong. The Django Way for this chapter is a maintained package that already does them, configured for Otahque’s rules.

Common Error: an email setting from older tutorials

Many tutorials tell you to set EMAIL_BACKEND for allauth’s emails. Django 6.1 configures email with MAILERS, which Otahque has had since Chapter 6, and adding EMAIL_BACKEND beside it stops every command with ImproperlyConfigured: Deprecated email settings are not allowed when MAILERS is defined. Leave MAILERS as it is: allauth’s confirmation emails already appear in the terminal.

Common Error: provider apps without their extra

Installing django-allauth without [socialaccount] and then listing the Google provider stops with ModuleNotFoundError: No module named 'requests'. The providers need the optional packages. Run the uv add command above, with the extra.

PASSWORD = 'a-long-safe-pass-123'


class ProfileTests(TestCase):
    """The profile page: your own name and time zone."""

    url = '/accounts/profile/'

    @classmethod
    def setUpTestData(cls):
        cls.sai = User.objects.create_user(
            'sai@example.org', PASSWORD, display_name='Sai'
        )

    def test_a_visitor_is_sent_to_sign_in(self):
        response = self.client.get(self.url)
        sign_in = reverse('account_login')
        self.assertRedirects(
            response, f'{sign_in}?next={self.url}',
            fetch_redirect_response=False,
        )

    def test_a_profile_is_made_the_first_time(self):
        self.assertFalse(Profile.objects.exists())
        self.client.force_login(self.sai)
        response = self.client.get(self.url)
        self.assertContains(response, 'value="Sai"')
        made = Profile.objects.get()
        self.assertEqual(made.user, self.sai)

    def test_name_and_zone_are_saved(self):
        self.client.force_login(self.sai)
        response = self.client.post(self.url, {
            'display_name': 'Sai K',
            'timezone': 'Europe/London',
        })
        self.assertRedirects(response, self.url,
                             fetch_redirect_response=False)
        self.sai.refresh_from_db()
        self.assertEqual(self.sai.display_name, 'Sai K')
        self.assertEqual(self.sai.profile.timezone,
                         'Europe/London')

    def test_an_unknown_zone_is_refused(self):
        self.client.force_login(self.sai)
        response = self.client.post(self.url, {
            'display_name': 'Sai', 'timezone': 'Mars/Base',
        })
        self.assertEqual(response.status_code, 200)
        self.assertFalse(Profile.objects.filter(
            timezone='Mars/Base').exists())

    def test_crafted_fields_change_nothing(self):
        self.client.force_login(self.sai)
        self.client.post(self.url, {
            'display_name': 'Sai', 'timezone': '',
            'email': 'boss@example.org', 'is_staff': 'on',
            'user': '999',
        })
        self.sai.refresh_from_db()
        self.assertEqual(self.sai.email, 'sai@example.org')
        self.assertFalse(self.sai.is_staff)

    def test_profile_csrf_is_checked(self):
        browser = Client(enforce_csrf_checks=True)
        browser.force_login(self.sai)
        data = {'display_name': 'Forged', 'timezone': ''}
        refused = browser.post(self.url, data)
        self.assertEqual(refused.status_code, 403)
        page = browser.get(self.url)
        token = str(page.context['csrf_token'])
        sent = browser.post(
            self.url, data | {'csrfmiddlewaretoken': token}
        )
        self.assertEqual(sent.status_code, 302)

accounts/models.py (add at the end)

class Profile(models.Model):
    """A member's own settings, one row per member."""

    user = models.OneToOneField(
        settings.AUTH_USER_MODEL,
        on_delete=models.CASCADE,
        related_name='profile',
    )
    timezone = models.CharField(
        max_length=64, blank=True,
        validators=[validate_timezone_name],
        help_text='Blank means not set.',
    )

    def __str__(self):
        return f'Profile of {self.user}'

    @classmethod
    def of(cls, user):
        """Return the member's profile, making it if new."""
        return cls.objects.get_or_create(user=user)[0]

OneToOneField is a foreign key that allows one profile per user, and related_name='profile' lets you write user.profile. on_delete=models.CASCADE deletes the profile with its member, because a profile means nothing alone. The time zone reuses Chapter 21’s validator, and blank means “not set”. Profile.of() returns the member’s profile and makes it the first time.

from allauth.account.adapter import DefaultAccountAdapter
from disposable_email_domains import blocklist
from django import forms
from django.conf import settings

DISPOSABLE = 'Please use a permanent email address.'


class AccountAdapter(DefaultAccountAdapter):
    """Otahque's choices inside allauth's sign-up."""

    def clean_email(self, email):
        """Refuse disposable domains unless allowed."""
        email = super().clean_email(email)
        domain = email.rsplit('@', 1)[-1].lower()
        allowed = settings.EMAIL_DOMAINS_ALLOWED
        if domain in blocklist and domain not in allowed:
            raise forms.ValidationError(DISPOSABLE)
        return email

def provider_sign_in(provider, email, uid='1'):
    """Sign in as if the provider confirmed this email.

    Returns the response and a client on that session.
    """
    request = RequestFactory().get('/')
    request.session = SessionStore()
    request.session.save()
    request._messages = FallbackStorage(request)
    request.user = AnonymousUser()
    found = get_social_adapter().get_provider(request,
                                              provider)
    login = SocialLogin(
        user=User(email=email),
        account=SocialAccount(provider=provider, uid=uid,
                              extra_data={'email': email}),
        email_addresses=[EmailAddress(
            email=email, verified=True, primary=True,
        )],
        provider=found,
    )
    with request_context(request):
        response = complete_social_login(request, login)
    request.session.save()
    browser = Client()
    key = request.session.session_key
    browser.cookies['sessionid'] = key
    return response, browser

docs/adr/ADR-003-accounts-allauth.md

# ADR-003: Member accounts with django-allauth

## Status

Proposed, November 2026 (Chapter 27). The choice of
django-allauth is the user's decision of 13 November 2026;
this record is not yet reviewed or accepted.

## Context

Members need to sign up, sign in, and sign out on Otahque's
own pages, with the email-only user of ADR-002, and to sign
in with Google or GitHub. Accounts must not be linked by an
email address alone, temporary addresses are refused, and
two-factor sign-in follows in Chapter 29.

## Options

- A: Django's own views (LoginView, LogoutView) and forms
  written for sign-up; social sign-in added later by hand.
- B: social-auth-app-django for providers, with Django's
  views for everything else.
- C: django-allauth for sign-up, sign-in, sign-out, email
  addresses, providers, rate limits, and later two-factor
  sign-in.

## Decision

Option C: `django-allauth[socialaccount]==65.22.1`, with
`disposable-email-domains==0.0.295` for refusing temporary
addresses. Email-only settings (no username field); an
extra sign-up form for the display name and time zone; an
account adapter that refuses disposable domains; provider
credentials read from .env; automatic sign-up through a
provider turned off, so every member gives a display name;
an email already registered is never connected without
signing in to that account first.

## Consequences

- Eleven more packages (the social extra brings requests,
  pyjwt, cryptography, and their dependencies); each pin is
  upgraded on purpose, with the test suite run first.
- allauth's templates are overridden in templates/allauth/
  to use Otahque's layout and field styles.
- The admin's own sign-in page bypasses allauth until
  Chapter 29 wraps it with secure_admin_login.
- Rate limits use the cache; one process is enough locally,
  and a shared cache is needed in production (Chapter 57).

## Revisit when

# Sign-up and sign-in: low-level design

Status: Drafted in Chapter 27, for review. Not approved.
Library: django-allauth (ADR-003), with accounts.User
(ADR-002).

## Pages

- /accounts/signup/: email, display name, time zone
  (optional), password twice. allauth's form plus
  accounts.forms.SignupForm. The email passes Django's
  validator, then AccountAdapter.clean_email(): refused if
  its domain is on the disposable-domains list and not in
  EMAIL_DOMAINS_ALLOWED. The address is stored in lower
  case (Chapter 21). A confirmation email is sent;
  verification is optional until Chapter 43.
- /accounts/login/: email (any letter case) and password.
  The session key changes on sign-in. Rate limits apply.
- /accounts/logout/: GET asks; POST signs out.
- /accounts/profile/: login required; edits the signed-in
  member's display name and Profile.timezone; reads no id
  from the address, so no other member can be reached.
  Profile.of(user) makes the profile the first time.
- /accounts/email/, /accounts/password/...: allauth's
  pages; taught in Chapter 29.

## Providers

- Google and GitHub, shown only when their client IDs are
  in .env; secrets never in Git or the database.
- A first sign-in shows the sign-up form (automatic
  sign-up is off), so a display name is always given.
- An email that already has an account: "An account already
  exists with this email address. Please sign in to that
  account first, then connect your ... account." Nothing is
  linked by email alone.
- A signed-in member connects a provider at
  /accounts/3rdparty/.
