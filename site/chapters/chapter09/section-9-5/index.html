Checkpoint: Quiz and Challenge

Quiz

Que. 3 What is the route string for the home address /?

Flip to check your answerFold answer back

Answer. The empty string, ''. The slash in the browser address is not included in the route argument.

Que. 4 Why do we have two files named urls.py?

Flip to check your answerFold answer back

Answer. The project URLconf chooses where to delegate; the events URLconf owns the app’s route patterns. They are in different folders and cooperate through include().

Que. 5 You open /events without the final slash, and the browser ends up at /events/. No route is named events. What happened?

Flip to check your answerFold answer back

Answer. Django’s CommonMiddleware found no match for /events but saw that /events/ would match, so it answered with a redirect, because the APPEND_SLASH setting is on by default. That is why this works in the browser, and why a test that requests /events receives a 301 rather than the page.

Que. 6 What does reverse('events:list') provide?

Flip to check your answerFold answer back

Answer. The path for the named route, /events/, in this configuration. It does not send a request.

Que. 7 Why check content as well as status 200, and why did we watch the tests fail first?

Flip to check your answerFold answer back

Answer. A successful response could still be from the wrong view or contain the wrong text, and a content assertion catches that, although it is not a complete browser or accessibility test. Watching a test fail first shows that it can fail, and that it fails for the reason we expected.

Mini-Challenge

Add a temporary route and trace an address. Work it out before reading the model answer, and remove the temporary route afterwards so that the next chapter starts from the same checkpoint.

Que. 8 Add a temporary welcome/ route in events/urls.py that uses the existing home view and has the name welcome. Visit /welcome/ locally, then trace /events/?page=2 through both URLconfs. What does each show, and does the page value alter the route?

Flip to check your answerFold answer back

Answer. Add path('welcome/', views.home, name='welcome'), inside the app’s urlpatterns. After saving, /welcome/ displays Welcome to Otahque. For /events/?page=2, the project includes events.urls at the empty prefix. The app’s events/ route selects event_list, which returns Event list coming soon. The query string does not change the match, and our current view does not use the page value. Remove only the temporary line and rerun the three tests.

What We Learned

  • A URL contains several parts; Django’s URL dispatcher matches the request path.
  • A project URLconf can include an app URLconf, and pattern order affects which view wins.
  • A named route can be reversed into a path; a view supplies the response.
  • A test written first and seen to fail shows that it can catch the problem; ., F, and E report each result.
  • Browser checks and automated tests give different, complementary evidence.

Git Commit

Once the checks pass, see what changed, in PowerShell, a macOS shell, or Linux/WSL Bash:

Terminal

git status --short

Expected result:

Output

 M config/urls.py
 M events/tests.py
 M events/views.py
?? events/urls.py

M marks a recorded file that has changed. Check that your secret .env is absent from the list. Stage only the four routing files, and read what you have staged; press q to leave the listing:

Terminal

git add config/urls.py events/views.py events/urls.py
git add events/tests.py
git diff --cached

If you see a secret, stop and follow Chapter 8’s secret recovery guidance in Table 8.4; removing it from a later commit does not erase earlier history. Otherwise, record the commit. No remote or push is needed:

Terminal

git commit -m "Add first routes and tests"
