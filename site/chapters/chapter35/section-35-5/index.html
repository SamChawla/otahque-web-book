Checkpoint: Quiz and Challenge

Quiz

Que. 1 What does as_view() return, and why can a URL pattern not use the class itself?

Flip to check your answerFold answer back

Answer. A function. Django calls whatever a pattern holds with the request and the URL’s values, and expects a response back. Calling a class makes an instance instead, so as_view() returns a function that makes an instance for each request, runs setup(), and returns what dispatch() returns.

Que. 2 The event page answered 200 to DELETE as a function and 405 as a class. Where does the 405 come from?

Flip to check your answerFold answer back

Answer. From View.dispatch(). It looks for a method named delete on the instance, finds none, and calls http_method_not_allowed(), which answers 405 with an Allow header built from the handlers the class has: GET, HEAD, OPTIONS.

Que. 3 Why did Step 7 accept the event page’s new answers, but Step 9 refuse the details page’s?

Flip to check your answerFold answer back

Answer. The event page never chose its answers to other methods; the class filled a gap with HTTP’s expected answer. The details page’s answers were chosen in Chapter 31 with require_http_methods above login_required, and a refactor should not undo a decision silently.

Que. 4 method_decorator([require_http_methods(['GET', 'POST']), login_required], name='dispatch'): which check runs first?

Flip to check your answerFold answer back

Answer. The method check. A list is applied in list order, the first outermost, just as stacked decorators read from the top, so a PUT gets 405 before sign-in is considered.

Que. 5 Why should a view not load its event in setup()?

Flip to check your answerFold answer back

Answer. setup() runs before dispatch(), and the decorators wrap dispatch(). Anything in setup() happens before sign-in is checked, so a signed-out visitor can get 404 where the page should send them to sign in.

Mini-Challenge

Chapter 36 will turn My registrations, my_registrations, into a ListView. Following ADR-006 rule 1, pin its answers first, in a new file, registrations/tests/test_mine.py. Predict each row before you run it.

Hint: read the function’s decorators. Which checks does it make, and which does it not?

Model answer: the function has login_required and nothing else, so a signed-out visitor is sent to sign in whatever the method, and a signed-in member gets the page whatever the method:

registrations/tests/test_mine.py

"""How My registrations answers every method.

Pinned before Chapter 36 makes the page a ListView.
"""
from django.test import TestCase

from config.helpers import answers

from .test_registrations import url, verified

MINE = [
    ('GET', 'sign in', 'ok'),
    ('HEAD', 'sign in', 'ok'),
    ('POST', 'sign in', 'ok'),
    ('PUT', 'sign in', 'ok'),
    ('DELETE', 'sign in', 'ok'),
    ('OPTIONS', 'sign in', 'ok'),
]


class MyRegistrationsMethodTests(TestCase):
    """My registrations' answer to each method, pinned."""

    @classmethod
    def setUpTestData(cls):
        cls.sai = verified('sai@example.org')

    def test_my_registrations(self):
        for method, signed_out, signed_in in MINE:
            with self.subTest(method):
                self.assertEqual(
                    answers(url('mine'), self.sai, method),
                    (signed_out, signed_in),
                )

What We Learned

  • A class-based view answers each HTTP method with a method of the same name; View supplies the machinery.
  • as_view() returns a function; each request gets a new instance; setup() runs, then dispatch() picks the handler or answers 405.
  • A class answers HEAD (with get()), OPTIONS (with options()), and other methods (405 with Allow) before your code runs.
  • A method table pins a page’s answer to every method, signed in and signed out, before any change; the existing suite did not.
  • Where a function chose its answers, keep them: move its decorators, in order, into one method_decorator list on dispatch().
  • Where a function chose nothing, accept Django’s answers on purpose and declare them in the table.
  • Decorators on dispatch() run after setup(); load objects that depend on the visitor in dispatch() or the handlers.
  • A labelled list (<dl>) shows facts as pairs a screen reader keeps together; one shared component serves two pages.
  • ADR-006 records which views become classes and which stay functions, with a reason for each.
