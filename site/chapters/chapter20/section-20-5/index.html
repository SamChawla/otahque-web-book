Checkpoint: Quiz and Challenge

Quiz

Que. 2 A registration belongs to one event, and an event has many registrations. On which table is the foreign key, and what is its column called?

Flip to check your answerFold answer back

Answer. On the registration table, the many side: registrations_registration. The field is named event, so its column is event_id, holding the event’s primary key. The event table has no column for its registrations; meetup.registrations asks the registration table.

Que. 3 What is meetup.registrations, and why does for booking in meetup.registrations: fail?

Flip to check your answerFold answer back

Answer. It is a related manager: a manager limited to the meetup’s registrations, named by related_name. A manager starts queries but is not a list of rows, so looping over it raises TypeError: 'RelatedManager' object is not iterable. meetup.registrations.all() returns a QuerySet you can loop over.

Que. 4 Event.objects.filter(registrations__status='active') returned the meetup twice. Why, and what fixes it?

Flip to check your answerFold answer back

Answer. The filter joins each event to its registrations, and the meetup has two active ones, so the join yields two meetup rows. distinct() returns each event once.

Que. 5 What does PROTECT cost Otahque, and why is it still the right rule for registrations?

Flip to check your answerFold answer back

Answer. An event or a member that registrations point at cannot be deleted, so closing a member’s account needs a deliberate design, in Chapters 27 and 65. It is still right because registrations are records that the product’s rules and the ERD keep: CASCADE would erase them silently whenever someone deleted a parent row.

Mini-Challenge

Que. 6 Sam asks: “Which events does Sai have an active registration for, each listed once, soonest first?” In the shell, without changing any rows, write one QuerySet that answers him, print its titles, and predict, before running it, how many queries printing the titles runs. Then check your prediction with CaptureQueriesContext.

Flip to check your answerFold answer back

Answer. One QuerySet, two conditions across the same relationship, and distinct(). Here is one session that answers it:

Django shell

>>> from django.test.utils import CaptureQueriesContext
>>> sai = User.objects.get(email='sai@example.org')
>>> mine = Event.objects.filter(
...     registrations__member=sai,
...     registrations__status=Registration.Status.ACTIVE,
... ).distinct()
>>> with CaptureQueriesContext(connection) as queries:
...     print([event.title for event in mine])
...
['Python meetup', 'Django workshop']
>>> len(queries)
1

Both conditions are in one filter() call, so they must hold for the same registration: an active registration that is Sai’s. Django’s documentation points out that two separate filter() calls across a many-valued relationship could match two different registrations instead. distinct() guards against an event appearing twice; until Chapter 21’s constraint, nothing stops two active registrations for the same member and event. The model’s ordering lists the events soonest first, and the list comprehension runs exactly one query. An answer that starts from sai.registrations and reads each registration’s event also works, but runs a query per row unless it uses select_related('event').

What We Learned

  • A ForeignKey is the many side of a one-to-many relationship: a column ending _id, a database constraint, and an index; OneToOneField adds uniqueness, and ManyToManyField uses a third table.
  • Relations to the user model use settings.AUTH_USER_MODEL; relations to another app’s model can use a string such as 'events.Event'.
  • on_delete states what a relationship means: PROTECT keeps history by refusing deletes, CASCADE deletes dependent rows, and Django 6.1’s DB_ rules hand the work to the database.
  • Forward access, booking.event, follows the key; reverse access, meetup.registrations, is a related manager named by related_name.
  • The double underscore follows relationships in filters, in both directions; reverse filters can repeat rows, and distinct() removes the repeats.
  • Reading a related object in a loop runs a query per row; select_related() joins forward relations into one query, and prefetch_related() fetches reverse ones in one more.
  • A new app is created with startapp, installed in INSTALLED_APPS, and gets its own migrations, which can depend on other apps’ migrations.
