How We Build It

Start from Chapter 20, in the folder containing manage.py, with your own .env, the locked environment, 36 passing tests, every migration applied, and the rows from Chapter 20: Sam, Sai, and Raj, three events, Sam’s organizer assignment, and three active registrations. Step 2 adds some deliberately bad rows. Step 3 writes the tests first. Steps 4 and 5 add the rules to events/models.py and registrations/models.py, and Step 6 finds and fixes the bad rows, then creates and applies two migrations. Step 7 changes accounts/managers.py and accounts/models.py for the email decision, with a third migration. Step 8 watches the database refuse bad rows, and Step 9 updates the ERD and commits. At the end, 51 tests pass and the public pages are unchanged.

The Custom Way

This illustration plays out Sai’s double-click with plain sqlite3, in memory; do not add it to the project. Instead of two real requests at the same time, it runs each request’s check before either insert, which is the order that matters:

illustration_only/two_requests.py (not part of the project)

import sqlite3

db = sqlite3.connect(':memory:')
db.execute('''
    CREATE TABLE place (event INTEGER, member TEXT,
                        status TEXT)
''')


def has_place(event, member):
    found = db.execute(
        "SELECT 1 FROM place WHERE event = ? AND member = ?"
        " AND status = 'active'", (event, member)
    ).fetchone()
    return found is not None


def add_place(event, member):
    db.execute("INSERT INTO place VALUES (?, ?, 'active')",
               (event, member))


first_free = not has_place(1, 'Sai')    # request A checks
second_free = not has_place(1, 'Sai')   # request B checks
if first_free:
    add_place(1, 'Sai')                 # request A inserts
if second_free:
    add_place(1, 'Sai')                 # request B inserts
print(db.execute('SELECT COUNT(*) FROM place').fetchone())

db.execute('DELETE FROM place')
db.execute("CREATE UNIQUE INDEX one_active ON place"
           " (event, member) WHERE status = 'active'")
add_place(1, 'Sai')
try:
    add_place(1, 'Sai')
except sqlite3.IntegrityError as error:
    print('refused:', error)
print(db.execute('SELECT COUNT(*) FROM place').fetchone())

Output

(2,)
refused: UNIQUE constraint failed: place.event, place.member
(1,)

Both checks found no active place, so both inserts ran, and Sai holds two places. After CREATE UNIQUE INDEX ... WHERE, the hand-written partial index, the second insert is refused by the database itself, however the checks went. Now list what the hand-written version still lacks: the index lives outside any model, so nothing keeps it in step with the code; the error is a bare sqlite3 message for programmers; and nothing can check the rule before saving to show a member a sentence. UniqueConstraint gives you all three.

Chapter 16 used SimpleTestCase because full_clean() then needed no database. From this chapter, full_clean() also checks the model’s constraints, and that asks the database, which SimpleTestCase forbids.

Common Error: database queries are not allowed in SimpleTestCase

If you skip that change, test_status_starts_draft_and_is_checked fails after Step 4 with DatabaseOperationForbidden: Database queries to 'default' are not allowed in SimpleTestCase subclasses. The traceback passes through validate_constraints(). Change the class to TestCase, which gives each test a database inside a transaction.

Then add a class at the end of the file, after OrganizerAssignmentTests:

events/tests.py (3 of 3: add at the end)

class EventRuleTests(TestCase):
    def test_capacity_must_be_more_than_zero(self):
        with self.assertRaises(IntegrityError):
            with transaction.atomic():
                save_event(capacity=0)
        self.assertFalse(Event.objects.exists())

    def test_end_must_be_after_start(self):
        start = datetime(2027, 2, 1, 18, tzinfo=UTC)
        with self.assertRaises(IntegrityError):
            with transaction.atomic():
                save_event(starts_at=start, ends_at=start)
        self.assertFalse(Event.objects.exists())

    def test_only_listed_statuses_can_be_saved(self):
        for status in Event.Status.values:
            save_event(status=status)
        with self.assertRaises(IntegrityError):
            with transaction.atomic():
                save_event(status='archived')
        self.assertEqual(Event.objects.count(), 3)

    def test_unknown_time_zone_fails_validation(self):
        event = save_event(timezone='Europe/Londn')
        with self.assertRaises(ValidationError) as caught:
            event.full_clean()
        self.assertEqual(
            caught.exception.message_dict,
            {'timezone': [
                'Europe/Londn is not a known time zone.'
            ]},
        )

    def test_one_current_assignment_per_event(self):
        event = save_event()
        sam = User.objects.create_user(
            'sam@example.org', display_name='Sam'
        )
        first = OrganizerAssignment.objects.create(
            event=event, member=sam
        )
        with self.assertRaises(IntegrityError):
            with transaction.atomic():
                OrganizerAssignment.objects.create(
                    event=event, member=sam
                )
        day = timedelta(days=1)
        first.revoked_at = first.assigned_at + day
        first.save()
        OrganizerAssignment.objects.create(
            event=event, member=sam
        )
        self.assertEqual(
            event.organizer_assignments.count(), 2
        )

    def test_revoked_never_before_assigned(self):
        event = save_event()
        sam = User.objects.create_user(
            'sam@example.org', display_name='Sam'
        )
        early = OrganizerAssignment.objects.create(
            event=event, member=sam
        )
        day = timedelta(days=1)
        early.revoked_at = early.assigned_at - day
        with self.assertRaises(IntegrityError):
            with transaction.atomic():
                early.save()

Each refused write sits inside transaction.atomic(). A TestCase runs every test inside a transaction, and after a database error, that transaction cannot run another query. The inner atomic() block marks a point to roll back to, so the test can go on to check that nothing was saved. The status test saves one event for every value in Event.Status.values, then tries one value that is not in the list: if someone later adds a status to the model but not to the constraint, the loop fails and says so. The time-zone test saves first, which works, because only validation checks time zones, and then calls full_clean(). The assignment test revokes the first assignment and makes a new one, proving that the rule is “one current assignment”, not “one ever”.

registrations/tests.py (2 of 2: add at the end)

    def test_second_active_registration_is_refused(self):
        with self.assertRaises(IntegrityError):
            with transaction.atomic():
                Registration.objects.create(
                    event=self.event, member=self.member
                )
        self.assertEqual(
            self.event.registrations.count(), 1
        )

    def test_member_can_register_after_cancelling(self):
        self.registration.status = 'cancelled'
        self.registration.cancelled_at = timezone.now()
        self.registration.save()
        Registration.objects.create(
            event=self.event, member=self.member
        )
        active = self.event.registrations.filter(
            status=Registration.Status.ACTIVE
        )
        self.assertEqual(active.count(), 1)

    def test_cancelled_at_matches_status(self):
        rows = Registration.objects.filter(
            pk=self.registration.pk
        )
        for status, cancelled_at in [
            ('cancelled', None),
            ('active', timezone.now()),
        ]:
            with self.subTest(status=status):
                with self.assertRaises(IntegrityError):
                    with transaction.atomic():
                        rows.update(
                            status=status,
                            cancelled_at=cancelled_at,
                        )

    def test_cancelled_never_before_registered(self):
        rows = Registration.objects.filter(
            pk=self.registration.pk
        )
        day = timedelta(days=1)
        before = self.registration.registered_at - day
        with self.assertRaises(IntegrityError):
            with transaction.atomic():
                rows.update(status='cancelled',
                            cancelled_at=before)

    def test_full_clean_explains_a_duplicate(self):
        duplicate = Registration(
            event=self.event, member=self.member
        )
        with self.assertRaises(ValidationError) as caught:
            duplicate.full_clean()
        self.assertEqual(
            caught.exception.messages,
            ['This member already has a place at '
             'this event.'],
        )

The cancellation test uses update() on purpose: it writes without calling save(), which is exactly the path that only a constraint can guard. subTest() runs the same check for both wrong combinations and reports each separately. The order test dates a cancellation one day before the registration, the kind of row a careless import could write. The last test is the friendly side: full_clean() on a duplicate raises ValidationError with the message you will write in Step 5, before anything reaches the database.

Step 4: Add the event rules

Open events/models.py. Replace its three import lines with these imports and a validator function, so the file begins:

events/models.py (1 of 4: imports and a validator)

from zoneinfo import available_timezones

from django.conf import settings
from django.core.exceptions import ValidationError
from django.db import models
from django.utils import timezone


def validate_timezone_name(value):
    """Refuse names missing from the time-zone database."""
    if value not in available_timezones():
        raise ValidationError(
            '%(value)s is not a known time zone.',
            code='unknown_timezone',
            params={'value': value},
        )

A validator is a function that takes a value and raises ValidationError if the value is wrong. zoneinfo is the Python standard library’s time-zone module, which Chapter 16’s time-zone field already relied on, and available_timezones() returns the set of names it knows, read on Windows from the tzdata package in the project’s lock file. The message uses %(value)s with params, rather than an f-string, so that Django can later translate the sentence; code names the kind of error for code that checks it.

In the Event class, attach the validator to the time-zone field, which becomes:

events/models.py (2 of 4: the timezone field)

Common Error: Status inside Meta

Writing condition=models.Q(status__in=Status.values) stops the project with NameError: name 'Status' is not defined. A nested class such as Meta cannot see the names defined beside it in the model’s class body. Write the values out, as in the listing. In the same spirit, CheckConstraint(check=...) from older articles fails with TypeError: CheckConstraint.__init__() got an unexpected keyword argument 'check': Django 6.0 removed that spelling, and the argument is now condition.

Finally, replace OrganizerAssignment’s Meta class at the end of the file:

events/models.py (4 of 4: OrganizerAssignment's Meta)

    class Meta:

        constraints = [
            models.UniqueConstraint(

Step 7: Store email addresses in lower case

Open accounts/managers.py and add two methods to UserManager, after the line use_in_migrations = True:

accounts/managers.py (add after use_in_migrations)

    @classmethod
    def normalize_email(cls, email):
        """Store the whole address in lower case."""
        return super().normalize_email(email).lower()

    def get_by_natural_key(self, email):
        return super().get_by_natural_key(
            self.normalize_email(email)
        )

normalize_email() is the method Chapter 17’s create_user() already calls. Django’s version, which super() runs first, lower-cases only the domain; this one then lower-cases the whole address. It is a class method, as in Django, so it can be called on the class itself. get_by_natural_key() is the lookup that sign-in uses to find a member from the address they typed, so it normalizes the typed address in the same way before searching.

When something goes wrong

The TransactionManagementError row deserves a word. Inside a TestCase, a database error spoils the test’s transaction, and the next query fails with An error occurred in the current transaction. You can't execute queries until the end of the 'atomic' block. That is why every expected IntegrityError in Step 3 sits inside its own transaction.atomic().
