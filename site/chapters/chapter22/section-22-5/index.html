Checkpoint: Quiz and Challenge

Quiz

Que. 2 Why does Event.objects.filter(location='Virtual').published() work, while User.objects.filter(is_staff=True).create_user(...) fails?

Flip to check your answerFold answer back

Answer. published() is a method of EventQuerySet, and filter() returns an EventQuerySet, so the method is there. create_user() is a method of UserManager only; filter() returns a QuerySet, which does not have it, so Python raises AttributeError.

Que. 3 The detail view now passes Event.objects.published() to get_object_or_404(). What does a visitor see at a draft’s address, and how do you know nothing else changed?

Flip to check your answerFold answer back

Answer. A 404 page, as before: the shortcut calls get() on the published events only, finds nothing, and raises Http404. Chapter 19’s detail-page tests, unchanged, still pass.

Que. 4 For the Python meetup, Count('registrations') gives 2, but Count('registrations', filter=Q(registrations__status='active')) gives 1. Why?

Flip to check your answerFold answer back

Answer. The meetup has two registrations: Sai’s, which is active, and Raj’s, which is cancelled. The filter argument counts only the related rows that match, so Raj’s is left out.

Que. 5 In Step 10, the annotated events came back with ordered False, although Event has Meta.ordering. Why, and what fixes it?

Flip to check your answerFold answer back

Answer. An annotation over a relation groups rows with GROUP BY, and Django does not apply the model’s default ordering to grouped queries. Add an explicit order_by('starts_at').

Que. 6 In Step 9, exclude(later) counted two active registrations as breaking the rule. Chapter 21’s constraint cancelled_after_registered stores them without complaint. Why the difference, and why does the constraint still spell out Q(cancelled_at__isnull=True)?

Flip to check your answerFold answer back

Answer. The two treat an empty value differently. A comparison with NULL is neither true nor false. filter() keeps only rows where the condition is true, and exclude() keeps the rest, so the active rows, with no cancellation time, are counted as breaking it. A CHECK refuses only rows where the condition is false, so the database passes them, and on Django 6.1 full_clean() does the same. The isnull branch therefore changes nothing for the database; it states the intent, “never cancelled, or cancelled at or after registering”, so that a reader, and anyone who turns the condition into a query, gets the same answer as the constraint.

Mini-Challenge

Que. 7 Sam asks for the published events that take place in person, not online, and have at least one active place, latest first. Write it as one chained query in the shell, starting from published(), and predict the result before running it.

Flip to check your answerFold answer back

Answer. Only the Python meetup: the Django workshop is virtual. One query that answers it:

Django shell

>>> from django.db.models import Count, Q
>>> active = Q(registrations__status='active')
>>> (Event.objects.published()
...     .exclude(location='Virtual')
...     .alias(places=Count('registrations', filter=active))
...     .filter(places__gte=1)
...     .order_by('-starts_at'))
<EventQuerySet [<Event: Python meetup>]>

The parentheses around the whole chain let it span several lines. Each method returns a new QuerySet, so the order of exclude() and alias() does not matter here, but filter(places__gte=1) must come after the alias() that defines places, and order_by() is needed because the count groups the rows. An answer using annotate() instead of alias() is also correct; it adds places to each event as well.

What We Learned

  • A manager starts queries; a QuerySet method can be called anywhere in a chain. Methods that select rows belong on a custom QuerySet, attached with as_manager().
  • Moving a repeated rule into published() is a refactor: the page tests, unchanged, prove the pages behave the same and run the same queries.
  • A method that depends on the time takes now as an argument, so tests can fix the clock and a page uses one instant; upcoming(now) and past(now) split the list at that instant.
  • A deliberate change to what a page shows starts by changing the test that describes it.
  • A number shown for every row belongs in the query as an annotation, such as with_places(); computed per row in the template, it is an N+1.
  • get_object_or_404() accepts a QuerySet, so a detail view can look among published events only.
  • Q objects combine conditions with &, |, and ~; F compares one column with another, row by row.
  • A comparison with an empty value is not true, so exclude() returns rows with NULL; a rule must say what empty means.
  • order_by() replaces the model’s ordering; grouped queries ignore Meta.ordering, so add order_by() when the order matters.
  • annotate() adds a count to each row, aggregate() returns one dictionary, and Count(filter=...) counts only matching related rows.
  • Prefetch with a named QuerySet and to_attr loads exactly the related rows a page needs, in one extra query.
