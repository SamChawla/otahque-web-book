Checkpoint: Quiz and Challenge

Quiz

Que. 3 Why does the dump leave out content types, permissions, and groups, but keep the admin’s history?

Flip to check your answerFold answer back

Answer. migrate makes content types, permissions, and Chapter 30’s groups again on the new database, with new ids, so loading the old ones would collide with them. The admin’s history was made by people, using the admin, and exists nowhere else, so it moves. Its link to a content type is written by name, which finds the new id.

Que. 4 The settings say TEST: {'TEMPLATE': 'otahque_template'}. Why not use otahque itself as the template?

Flip to check your answerFold answer back

Answer. A copy of otahque would bring every real row into the test database, so tests would no longer start empty, and PostgreSQL refuses to copy a database while anyone is connected to it, such as a running development server. otahque_template is empty and has only one job: carrying the right sort order into every test database.

Que. 5 After the move, compare_databases.py prints skip django_session. Is something wrong?

Flip to check your answerFold answer back

Answer. No. Sessions were left out on purpose: they are short-lived sign-ins, not records. The only effect is that everyone signs in once more on PostgreSQL.

Que. 6 A reader’s .env has the line DB_ENGINE= with nothing after it. Which database does Django use, and how can the reader tell?

Flip to check your answerFold answer back

Answer. SQLite, because the settings treat an empty value as missing. uv run python check_environment.py shows it on its last line, sqlite followed by a version, instead of postgresql 18.

Mini-Challenge

Que. 7 Table 32.2 says contains now respects case. Write two tests in events/tests.py that show it on PostgreSQL: searching titles for “python” finds “Python clinic” with icontains and finds nothing with contains. Run them on PostgreSQL. Then say what the second test would do on SQLite, and why that is a reason to search with icontains.

Flip to check your answerFold answer back

Answer. At the end of events/tests.py:

events/tests.py (add at the end)

class TitleSearchTests(TestCase):
    """A search for a word in titles, on PostgreSQL."""

    @classmethod
    def setUpTestData(cls):
        save_event(title='Python clinic')

    def test_icontains_ignores_case(self):
        found = Event.objects.filter(title__icontains='python')
        self.assertEqual(found.count(), 1)

    def test_contains_keeps_case(self):
        found = Event.objects.filter(title__contains='python')
        self.assertEqual(found.count(), 0)

Terminal

uv run python manage.py test events -k TitleSearch

Output

Found 2 test(s).
Creating test database for alias 'default'...
...
Ran 2 tests in ...s

OK

On SQLite the second test fails: SQLite’s LIKE ignores case for the letters A to Z, so contains finds the title there too. The same query giving different answers on two databases is a reason to say what you mean, as Chapter 19 advised: icontains ignores case on both. Chapter 56 builds Otahque’s search. Remove both tests afterwards, or keep them as a record of the difference.

What We Learned

  • A database server runs on its own and serves many connections, signed in as roles; that is what makes row locks and Chapter 33 possible.
  • PostgreSQL 18 is pinned instead of the days-old 19, and psycopg 3’s binary package is pinned for development.
  • Settings read the database from .env; with no DB_ENGINE, earlier checkpoints still run on SQLite, and check_environment.py says which is in use.
  • Moving between engines: leave out what migrations make again, follow relations with natural foreign keys, keep each row’s own id, and write XML so times keep their microseconds.
  • loaddata resets the id sequences; rows inserted another way need sqlsequencereset.
  • A move is checked by comparing both databases, table by table, not by looking at pages.
  • Tests copy a template database; TEST['TEMPLATE'] gives them Otahque’s sort order, and the role needs CREATEDB.
  • A backup is proved by restoring it into a copy and comparing; the copy and every dump are removed afterwards, because they hold personal data.
  • inspectdb and managed = False read a table that another system owns, and the database role, not Django, refuses writes.
