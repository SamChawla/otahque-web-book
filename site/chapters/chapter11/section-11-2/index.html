What You Need to Know

HTML, templates, and context

In Chapter 3 we learned that a browser can interpret an HTML response as a page. HTML uses elements such as headings, paragraphs, lists, and links to describe structure. For example, an h1 element is a top-level heading; it is not just a way to make text large. A link’s href gives its destination. The browser reads the HTML and builds its own in-memory model of the page, called the DOM, short for document object model. So the raw HTML sent by the server and the text visible on the page are related but not identical, and that difference matters when we come to escaping.

New Concept: a template and its context

What problem exists? Our view needs to display data without constructing an entire HTML document in Python.

What did people do before? Programs joined strings by hand, which mixes page structure with application decisions and leaves every value to be escaped by remembering to do so.

What is a template? A file describing the output structure, with places for values and template instructions. Context is the collection of named values provided when the template is rendered.

Why templates? Page structure and application decisions can change separately, and Django escapes ordinary values on the way in.

Now let’s use it.

In a Django template, {{ title }} means “insert the value named title”. The braces belong to the template language and are not part of the displayed title. A tag such as {% for event in events %} controls rendering; {% empty %} provides an alternative when the collection has no items. The view chooses the data and calls render(request, template_name, context). Django loads the template, applies the context, and returns an HTML response.

Flip to check your answerFold answer back

Answer. No. It supplies named values. The template provides the structure, and rendering combines them into a response.

Where Django finds a template

Our Chapter 10 settings already include the Django template backend and APP_DIRS set to True. With this configuration, Django can search the templates directory of an installed app. We will place our files inside events/templates/events/. The repeated events folder is deliberate: it makes names such as events/list.html less likely to collide with another app’s list.html.

Under the Hood: Loading and rendering

The view calls render() with the request, a template name, and a context dictionary. Django asks its configured template engine to find the named file. The engine evaluates its variables and tags using that context, then the shortcut returns an HttpResponse containing the result. A wrong path or missing file raises a template-not-found error. The exact search depends on the project’s template settings and installed apps.

The existing events:detail route accepts an event ID. The template’s {% url %} tag can build the address from that name and ID; it does not invent an event. If the name or required argument is wrong, rendering can fail. The list and detail templates use the same in-memory sample dictionary that the view checks. There is still no database.

Escaping data for HTML

In HTML, characters such as <, >, &, and quotes have special meanings. HTML escaping represents them in a way that allows the browser to display the characters as text in an appropriate HTML context. For example, <strong> in an ordinary title becomes escaped output; the browser displays the characters instead of making a strong element from that value.

Django’s template language automatically HTML-escapes ordinary variable values by default. This is an important protection against cross-site scripting, often shortened to XSS, where attacker-controlled content is made to run as code in someone else’s browser. It is not a guarantee that every output context is safe. Marking untrusted data as safe or disabling autoescaping can bypass this protection. HTML escaping alone does not validate a URL or provide the right handling for arbitrary JavaScript or CSS. Choose protections for the context, and validate data for its intended purpose.

In practice: a surprising title

Situation. A fictional sample title contains angle brackets that look like an HTML tag.

Application. The template renders the ordinary title as text using automatic escaping, so the browser shows the brackets instead of treating them as markup.

Consideration. The displayed text and the raw HTML differ, and neither this one example nor a passing test proves every context safe.

Que. 2 Why is it risky to apply safe to an untrusted title just because it contains markup?
