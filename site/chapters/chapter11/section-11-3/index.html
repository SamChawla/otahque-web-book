How We Build It

Start from Chapter 10 in the directory containing manage.py, with your own .env, the locked environment, and six passing tests. We will change events/tests.py and events/views.py, then add events/templates/events/list.html and events/templates/events/detail.html. The existing events/urls.py remains in place. We add no dependency, migration, model, or external service.

The Custom Way

This illustration shows the problem; do not add it to the project or run it with untrusted data:

illustration_only/unsafe_heading.py (not part of the project)

def unsafe_heading(title):
    return '<h1>' + title + '</h1>'

If title contains HTML-looking text, simple concatenation does not escape it. Writing the page this way would put the burden on us to handle each output context correctly. Our actual project uses Django’s template engine and keeps autoescaping enabled.

The Django Way

Step 1: Change the tests first

In events/tests.py, replace the file with the complete listing below. The Chapter 10 home, route, and 404 checks remain. The list and detail assertions change because these responses will now be HTML rather than the old placeholder and plain-text result. patch.dict temporarily changes the sample dictionary inside one test and restores it afterwards; it does not change your project file.

events/tests.py

"""Tests for the events app."""
from unittest.mock import patch

from django.test import SimpleTestCase
from django.urls import resolve, reverse

from . import views


class RoutingTests(SimpleTestCase):
    """Each address reaches its view; others are not found."""

    def test_home(self):
        response = self.client.get('/')
        self.assertContains(
            response, 'Welcome to Otahque.'
        )
        self.assertEqual(reverse('events:home'), '/')
        self.assertIs(resolve('/').func, views.home)

    def test_event_list(self):
        response = self.client.get('/events/')
        self.assertContains(response, 'Python meetup')
        self.assertTemplateUsed(
            response, 'events/list.html'
        )
        self.assertContains(
            response, 'href="/events/1/"'
        )
        self.assertEqual(
            reverse('events:list'), '/events/'
        )
        self.assertIs(
            resolve('/events/').func, views.event_list
        )

    def test_unknown_path(self):
        response = self.client.get('/does-not-exist/')
        self.assertEqual(response.status_code, 404)


class EventDetailTests(SimpleTestCase):
    """One event by number, and the 404 for any other."""

    def test_sample_event(self):
        response = self.client.get('/events/1/')
        self.assertContains(
            response, 'Sample: Python meetup'
        )
        self.assertTemplateUsed(
            response, 'events/detail.html'
        )
        self.assertTrue(
            response['Content-Type'].startswith(
                'text/html'
            )
        )

    def test_missing_event(self):
        self.assertIs(
            resolve('/events/999/').func,
            views.event_detail,
        )
        response = self.client.get('/events/999/')
        self.assertEqual(response.status_code, 404)

    def test_invalid_id(self):
        response = self.client.get('/events/abc/')
        self.assertEqual(response.status_code, 404)


class TemplateSafetyTests(SimpleTestCase):
    """Templates escape titles; an empty list says so."""

    def test_empty_list(self):
        with patch.dict(
            views.SAMPLE_EVENTS, {}, clear=True
        ):
            response = self.client.get('/events/')
        self.assertContains(
            response, 'No sample events yet.'
        )

    def test_list_escapes_title(self):
        title = '<strong>Not a tag</strong>'
        with patch.dict(
            views.SAMPLE_EVENTS, {1: title}, clear=True
        ):
            response = self.client.get('/events/')
        self.assertContains(
            response, '&lt;strong&gt;'
        )
        self.assertNotContains(
            response, '<strong>Not a tag'
        )

    def test_detail_escapes_title(self):
        title = '<strong>Not a tag</strong>'
        with patch.dict(
            views.SAMPLE_EVENTS, {1: title}, clear=True
        ):
            response = self.client.get('/events/1/')
        self.assertContains(
            response, '&lt;strong&gt;'
        )
        self.assertNotContains(
            response, '<strong>Not a tag'
        )

Step 2: Write the views

Replace events/views.py with the complete file below. The home view stays as it was. The list view transforms the fixed dictionary into a list of dictionaries, each with an ID and title, and passes it as events. The detail view still raises Http404 for an unknown ID; for an existing one it passes title to its template.

events/views.py

"""The events app's views: one function per page."""
from django.http import Http404, HttpResponse
from django.shortcuts import render

SAMPLE_EVENTS = {1: 'Python meetup'}


def home(request):
    """Welcome visitors to Otahque."""
    return HttpResponse('Welcome to Otahque.')


def event_list(request):
    """List Otahque's events."""
    events = [
        {'id': event_id, 'title': title}
        for event_id, title in SAMPLE_EVENTS.items()
    ]
    return render(
        request, 'events/list.html', {'events': events}
    )


def event_detail(request, event_id):
    """Show one event, or 404 if its number is unknown."""
    title = SAMPLE_EVENTS.get(event_id)
    if title is None:
        raise Http404('Sample event not found')
    return render(
        request, 'events/detail.html', {'title': title}
    )

The values inside SAMPLE_EVENTS are deliberately fictional and live only in the Python process. The render() shortcut constructs the HTML response. The context keys, events and title, must agree with the names in the templates.

Step 3: Add the sample list template

The templates need a folder inside the app. Create it in your editor, or with a command. In PowerShell, beside manage.py:

PowerShell

New-Item -ItemType Directory -Force events/templates/events

In a macOS shell or Linux/WSL Bash, beside manage.py:

Terminal

mkdir -p events/templates/events

Create list.html inside that inner folder and enter this complete file:

events/templates/events/list.html

<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport"
        content="width=device-width, initial-scale=1">
  <title>Sample events | Otahque</title>
</head>
<body>
  <main>
    <h1>Sample events</h1>
    <p>These fictional events are examples.</p>
    <ul>
      {% for event in events %}
        <li>
          <a href="{% url 'events:detail' event.id %}">
            {{ event.title }}
          </a>
        </li>
      {% empty %}
        <li>No sample events yet.</li>
      {% endfor %}
    </ul>
  </main>
</body>
</html>

The {% for %} tag repeats the list item for each event. The {% empty %} branch displays a message when there are none. The {% url %} tag uses the existing events:detail route and the current event’s ID. The browser sees a link; Django still checks the ID when its destination is requested.

Step 4: Add the detail template

Create events/templates/events/detail.html:

events/templates/events/detail.html

<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport"
        content="width=device-width, initial-scale=1">
  <title>Sample event | Otahque</title>
</head>
<body>
  <main>
    <h1>Sample: {{ title }}</h1>
    <p>This fictional event is an example.</p>
    <a href="{% url 'events:list' %}">All sample events</a>
  </main>
</body>
</html>

The title is inserted as an ordinary template variable in an HTML heading. The link uses the existing events:list name. Both pages label their data fictional. We keep their small repeated HTML structures for now; Chapter 12 will introduce inheritance and shared layouts.

Common Error: TemplateDoesNotExist

Check both events folder names and the filename. The view asks for events/list.html, while the file is inside the installed app at events/templates/events/list.html. Compare the path before creating or replacing anything else.

A misspelled variable is harder to notice, because it raises no error at all. {{ titel }} simply renders as nothing, and the heading reads Sample: with no title. That is one reason our tests look for the title itself, and not only for a 200 status.

Start the local server from the same directory:

Terminal

Open http://127.0.0.1:8000/events/, select Python meetup, and confirm the detail page says Sample: Python meetup. Visit http://127.0.0.1:8000/events/999/ and confirm a 404. Stop the server with Ctrl+C. Django may warn about unapplied migrations; do not apply them yet, because the custom user model is planned first. The test client checks responses, while a browser also lets you inspect the page and links.

When something goes wrong

Keep your work while you diagnose a problem. Compare each named file to the listing and save a separate copy before replacing anything you want to keep. Fix one issue and rerun the tests. Do not delete the project or reset Git as a first response.
