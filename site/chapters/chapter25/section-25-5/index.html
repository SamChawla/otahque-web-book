Checkpoint: Quiz and Challenge

Quiz

Que. 3 After form = EventForm(request.POST, instance=event) and form.is_valid() returns false, what does event.title hold, and what is stored?

Flip to check your answerFold answer back

Answer. event.title holds the title Sam typed, because is_valid() copies the cleaned values onto the instance before the model’s checks run. The stored row is unchanged, because nothing called save(). That is why the view reads the title before binding the form.

Que. 4 In which order do these run for an edit: the model’s clean(), the form’s clean(), clean_capacity(), and validate_constraints()?

Flip to check your answerFold answer back

Answer. clean_capacity(), then the form’s clean(), then the model’s clean(), then validate_constraints(). Field rules come first, then the form’s rules across fields, then the model’s checks, with the constraints last.

Que. 5 An administrator holds view_event and change_event but organizes no event. What do they get on Sam’s draft’s edit page, and where do they edit events instead?

Flip to check your answerFold answer back

Answer. 403 Forbidden: they may see the draft, through view_event, but can_be_edited_by() also needs a current organizer assignment. They edit events in the admin site, the administrator’s tool since Chapter 23.

Que. 6 Two members hold places at Sam’s clinic. Which layer refuses a capacity of 1, and which refuses 0? Where does each message appear?

Flip to check your answerFold answer back

Answer. The model’s clean() refuses 1, because it is below the two places taken, and the form shows the message beside Capacity. The form’s clean_capacity() refuses 0, also beside Capacity; behind both, the database’s constraint refuses 0 from anywhere.

Que. 7 Why does the form compare the text that comes back with self.shown instead of using form.changed_data?

Flip to check your answerFold answer back

Answer. changed_data compares the sent text with the initial value read in UTC, so it reports both times as changed even when Sam touched neither. The form knows the exact text it showed, so comparing text is exact, and it avoids reading a repeated hour again.

Mini-Challenge

Que. 8 Predict what the form does with three edits of Sam’s clinic, each sent with the clinic’s other values unchanged: the zone set to Asia/Kolkata; the same with the tick box ticked; and the start moved to 18:00 with the zone kept. For each valid one, give the start as the form will store it, with its offset from UTC. Then check with a practice file that only validates, so nothing is saved.

Flip to check your answerFold answer back

Answer. The first is refused, with the code zone_changed, because a new zone needs the tick box. The second is valid, and the start is 19:00 on 3 December in Kolkata, +05:30, which is 13:30 UTC. The third is valid: 18:00 on 3 December in New York, -05:00. One file that checks it, run with uv run python ../practice/challenge.py:

../practice/challenge.py

import setup_django
from events.forms import EventForm
from events.models import Event

SENT = {'title': 'Online Django clinic',
        'timezone': 'America/New_York',
        'starts_at': '2026-12-03T19:00',
        'ends_at': '2026-12-03T20:30',
        'location': 'Online', 'capacity': '50'}
EDITS = [{'timezone': 'Asia/Kolkata'},
         {'timezone': 'Asia/Kolkata', 'confirm_zone': 'on'},
         {'starts_at': '2026-12-03T18:00'}]
for edit in EDITS:
    clinic = Event.objects.get(title='Online Django clinic')
    form = EventForm(SENT | edit, instance=clinic)
    if form.is_valid():
        starts = form.cleaned_data['starts_at']
        print('valid, starts', starts.isoformat())
    else:
        error = form.errors.as_data()['timezone'][0]
        print('refused:', error.code)

Output

refused: zone_changed
valid, starts 2026-12-03T19:00:00+05:30
valid, starts 2026-12-03T18:00:00-05:00

isoformat() writes a date and time with its offset. The file sends 20:30 for Ends, not the 21:00 you saved in Step 5, so the form reads that time again; the three results are the same either way. The file calls no save(), so your rows are unchanged.

What We Learned

  • EventForm(request.POST, instance=event) edits one row with the same fields and rules as creating it; save() updates that row.
  • is_valid() runs field rules, clean_<name>(), the form’s clean(), copies values onto the instance, then the model’s clean_fields(), clean(), unique checks, and constraints; only save() writes.
  • The instance changes even when the form is invalid, so read saved values before binding.
  • Model permissions answer “may this person change events?”; an ownership check answers “this event?”. Check visibility first: 404 for the hidden, 403 for the refused.
  • Show stored times in the event’s zone, keep text that was not changed, and confirm a change of zone with both readings shown together.
  • A rule across two tables, such as capacity against places taken, lives in the model’s clean(), so every ModelForm, the admin’s included, obeys it; a lock comes in Chapter 33.
  • The allowlist protects edits too, and tests that pass at once can guard a rule that is already in place.
  • The last save wins until Chapter 33 adds a version check.
