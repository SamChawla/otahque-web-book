Checkpoint: Quiz and Challenge

Quiz

Que. 3 What does a child template’s {% extends "base.html" %} tell Django?

Flip to check your answerFold answer back

Answer. To render base.html as the page, using the child’s blocks in place of the parent’s blocks with the same names.

Que. 4 A child fills a block named contnet. What happens?

Flip to check your answerFold answer back

Answer. Nothing visible and no error. The parent defines no such block, so its content is dropped. The page still returns 200, which is why our tests check for content.

Que. 5 What context does an included template see, and how can you limit it?

Flip to check your answerFold answer back

Answer. The same context as the template that includes it. with passes extra values, and only restricts it to those values.

Que. 6 What does inline add to {% partialdef %}?

Flip to check your answerFold answer back

Answer. It renders the partial where it is defined, as well as defining it. Without inline, nothing appears until {% partial %} uses it.

Que. 7 Why does sample_label use format_html instead of joining strings and calling mark_safe?

Flip to check your answerFold answer back

Answer. format_html escapes the title before inserting it and marks only the finished result safe. Joining first would mark an unescaped title safe and switch off the protection the escaping tests check.

Mini-Challenge

Work in a separate copy of your project, so your checkpoint stays as it is. Django also offers inclusion tags: a function that chooses context and renders its own small template, used as {% event_card event %}.

Que. 8 In the copy, add an event_card inclusion tag to event_labels.py that renders events/event_card.html with a linked, labelled title. Write a test first that renders the tag with a title containing <b> and checks the link and the escaped title.

Flip to check your answerFold answer back

Answer. The test renders a tiny template, as the filter tests do:

events/tests.py (challenge copy only)

class EventCardTagTests(SimpleTestCase):
    def test_card_links_and_escapes(self):
        template = Template(
            '{% load event_labels %}{% event_card event %}'
        )
        event = {'id': 1, 'title': '<b>Not a tag</b>'}
        html = template.render(Context({'event': event}))
        self.assertIn('href="/events/1/"', html)
        self.assertIn('&lt;b&gt;Not a tag', html)

Add the tag below the filter in event_labels.py:

events/templatetags/event_labels.py (challenge)

@register.inclusion_tag('events/event_card.html')
def event_card(event):
    return {'event': event}

Create events/templates/events/event_card.html. It loads the library itself, because an inclusion tag’s template is rendered on its own:

events/templates/events/event_card.html (challenge)

{% load event_labels %}
<article>
  <a href="{% url 'events:detail' event.id %}">
    {{ event.title|sample_label }}
  </a>
</article>

The test fails until the tag and template exist, then all 15 tests in the copy pass. An inclusion tag suits a piece that needs its own context, used across many templates. Leave your main project at 14 tests for Chapter 13.

What We Learned

  • A base template holds the shared structure, and child templates fill its named blocks.
  • Inheritance mistakes such as a misspelled block are silent, so tests check content.
  • A project templates folder, found through DIRS, holds what no single app owns.
  • include inserts a self-contained template with the current context, limited by with and only.
  • A partial names a fragment inside one template and can be rendered alone with template#partial.
  • A custom filter that adds HTML uses format_html, so its input stays escaped.

Git Commit

Check the changes, then stage the new and changed files, in PowerShell, a macOS shell, or Linux/WSL Bash, beside manage.py. Read the staged changes, and press q to leave the listing:

Terminal

git status --short
git add config/settings.py templates events/views.py
git add events/tests.py events/templates events/templatetags
git diff --cached

The folder names add every file inside them. Keep .env out of Git, as before. Then record the commit:

Terminal

git commit -m "Share one layout and navigation across pages"
