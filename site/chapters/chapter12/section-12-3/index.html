How We Build It

Start from Chapter 11, in the directory containing manage.py, with your own .env, the locked environment, and nine passing tests. We will change events/tests.py, events/views.py, config/settings.py, and the two Chapter 11 templates. We will add templates/base.html, templates/includes/site_nav.html, events/templates/events/home.html, and a templatetags package with one module. events/urls.py does not change.

The Custom Way

This illustration shows the problem; do not add it to the project:

illustration_only/joined_page.py (not part of the project)

HEADER = '<nav><a href="/">Home</a></nav><main>'
FOOTER = '</main>'


def page(body):
    return HEADER + body + FOOTER

Every view would wrap its HTML in the same two strings. It works until one view forgets, a link changes and the header has to know it, or a body contains a title that is never escaped. The Django Way keeps the structure in a template and leaves escaping on.

The Django Way

class LayoutTests(SimpleTestCase):
    """Every page shares the base layout and navigation."""

    pages = [
        ('/', 'events/home.html', 'Otahque'),
        ('/events/', 'events/list.html',
         'Sample events | Otahque'),
        ('/events/1/', 'events/detail.html',
         'Sample event | Otahque'),
    ]

    def test_pages_extend_layout(self):
        for url, template, title in self.pages:
            with self.subTest(url=url):
                response = self.client.get(url)
                self.assertTemplateUsed(response, template)
                self.assertTemplateUsed(
                    response, 'base.html'
                )
                self.assertContains(
                    response, f'<title>{title}</title>',
                    html=True,
                )

    def test_pages_include_navigation(self):
        for url, template, title in self.pages:
            with self.subTest(url=url):
                response = self.client.get(url)
                self.assertTemplateUsed(
                    response, 'includes/site_nav.html'
                )
                self.assertContains(
                    response,
                    '<a href="/">Home</a>',
                    html=True,
                )
                self.assertContains(
                    response,
                    '<a href="/events/">Events</a>',
                    html=True,
                )


class EventRowPartialTests(SimpleTestCase):
    """The event row partial renders one event."""

    def test_row_renders_alone(self):
        event = {'id': 1, 'title': '<b>Not a tag</b>'}
        html = render_to_string(
            'events/list.html#event-row', {'event': event}
        )
        self.assertIn('href="/events/1/"', html)
        self.assertIn('&lt;b&gt;Not a tag', html)
        self.assertNotIn('<nav', html)


class SampleLabelFilterTests(SimpleTestCase):
    """The sample_label filter marks and escapes a title."""

    def render_label(self, title):
        """Render the filter on title, as a template would."""
        template = Template(
            '{% load event_labels %}{{ title|sample_label }}'
        )
        return template.render(Context({'title': title}))

    def test_labels_title(self):
        self.assertEqual(
            self.render_label('Python meetup'),
            '<span class="sample-label">Sample:</span>'
            ' Python meetup',
        )

    def test_escapes_title(self):
        title = '<strong>Not a tag</strong>'
        html = self.render_label(title)
        self.assertIn('&lt;strong&gt;', html)
        self.assertNotIn('<strong>', html)

LayoutTests checks all three pages with one loop. self.subTest(url=url) reports each page separately, so one failing page does not hide the others. The partial test renders one row alone and checks that it links to the event, escapes its title, and carries no navigation. The filter tests render a tiny template that loads our filter, the same way a page will use it.

Step 2: Add the project templates folder and the layout

Common Error: changing APP_DIRS instead of DIRS

APP_DIRS is True or False: it switches the search of app folders on or off. The project folder is added to the list in DIRS. Setting APP_DIRS to a path does not add a folder, and setting it to False would hide the Chapter 11 templates.

In config/settings.py, find the TEMPLATES setting and change only the DIRS line, so that it reads:

config/settings.py (in TEMPLATES)

        'DIRS': [BASE_DIR / 'templates'],

BASE_DIR is the folder containing manage.py, as Chapter 6 explained. Now create the folder for the layout. In PowerShell, beside manage.py:

PowerShell

New-Item -ItemType Directory -Force templates

In a macOS shell or Linux/WSL Bash, beside manage.py:

Terminal

mkdir -p templates

Create templates/base.html with this complete file:

templates/base.html

<!doctype html>

  <title>{% block title %}Otahque{% endblock %}</title>
</head>
<body>
  <main>
    {% block content %}{% endblock %}
  </main>
</body>
</html>

"""The events app's views: one function per page."""
from django.http import Http404
from django.shortcuts import render

SAMPLE_EVENTS = {1: 'Python meetup'}


def home(request):
    """Welcome visitors to Otahque."""
    return render(request, 'events/home.html')


def event_list(request):
    """List Otahque's events."""
    events = [
        {'id': event_id, 'title': title}
        for event_id, title in SAMPLE_EVENTS.items()
    ]
    return render(
        request, 'events/list.html', {'events': events}
    )


def event_detail(request, event_id):
    """Show one event, or 404 if its number is unknown."""
    title = SAMPLE_EVENTS.get(event_id)
    if title is None:
        raise Http404('Sample event not found')
    return render(
        request, 'events/detail.html', {'title': title}
    )

Step 5: Make the list row a partial

Common Error: an undefined partial name

{% partial row %} for a name that no partialdef defines fails with TemplateSyntaxError: Partial 'row' is not defined in the current template. Loading events/list.html#row from a view or test fails with TemplateDoesNotExist. Compare the name in both places, including hyphens.

Step 6: Add the filter and restart the server

Common Error: load is not inherited, and a new module needs a restart

A child that uses sample_label without its own {% load event_labels %} raises a TemplateSyntaxError ending Invalid filter: 'sample_label', even if its parent loads the library. If the development server was running when you created templatetags, it may report 'event_labels' is not a registered tag library until you stop it and start it again.

Create the package folder events/templatetags and an empty __init__.py inside it, which makes the folder a Python package. In PowerShell:

PowerShell

New-Item -ItemType Directory -Force events/templatetags
New-Item -ItemType File events/templatetags/__init__.py

In a macOS shell or Linux/WSL Bash:

Terminal

mkdir -p events/templatetags
touch events/templatetags/__init__.py

Create events/templatetags/event_labels.py:

events/templatetags/event_labels.py

"""Template filters and tags for event pages."""
from django import template
from django.utils.html import format_html

register = template.Library()


@register.filter
def sample_label(title):
    """Mark a title as fictional sample data, escaping it."""
    return format_html(
        '<span class="sample-label">Sample:</span> {}', title
    )

register is the library Django finds when a template says {% load event_labels %}; the module’s file name is the library’s name. @register.filter adds the function to it under its own name. format_html escapes title before putting it in place of {}.

  <p>These fictional events are examples.</p>
  <ul>
    {% for event in events %}
      {% partialdef event-row inline %}
        <li>

          </a>
        </li>

When something goes wrong

When the problem is inside a template file, Django starts a TemplateSyntaxError message with Template:, the file’s full path, and a comma. Table 12.2 leaves that part out and marks the gap with ...; the path tells you which file to open.

Keep your work while you diagnose a problem. Compare the one file the message names with its listing, and save a copy before replacing anything you want to keep. Fix one problem at a time and rerun the tests. Do not delete the project or reset Git as a first response.
