6.3 Read the generated files

Soni asks which file will eventually connect an event address to Python code. The generated project is small enough to answer that question by reading it. We will give each file one clear job before changing the application’s behaviour.

Starting point: Section 6.2’s project and successful system check. Work in otahque/ and open manage.py and the config/ files in your editor. No files need changing in this section. Your output is an annotated file map; rerunning the system check confirms that observation has not altered the configuration.

The command helper and the package

Open manage.py. Its main function selects config.settings and passes the terminal’s arguments to Django’s management machinery. In the check command, check is one of those arguments. You do not need to understand every line to use the helper, and you should leave it unchanged for now. The imports, function definition, and call are the Python structures from Chapter 4.

The empty config/__init__.py marks config as a regular Python package. A package groups importable Python modules. The dot in config.settings means the settings module inside that package; it is not a file extension and is different from the destination dot in startproject.

Settings choose components and values

Open config/settings.py. It is a Python module containing configuration values. Some are strings or Booleans; others are lists and dictionaries, which you practised in Chapter 4. You can recognize the shape before learning every setting.

The generated settings enable Django’s admin, account, session, and other supporting apps. That does not mean Otahque’s event behaviour or account pages have been implemented. We will configure these parts when their chapters need them. Chapter 8 develops settings and environments; later security and deployment chapters explain the production configuration.

Do not paste your SECRET_KEY into a public question or screenshot. The generated value begins with django-insecure- as a reminder that it suits local development only; a deployed system needs a different secret, kept out of shared code. We leave the generated debug and database settings alone for this local exercise.

URLs select the next piece of code

Open config/urls.py. The urlpatterns list currently contains a route for Django’s built-in admin site. This is the root URL configuration from Chapter 5. It does not yet contain an event route or an Otahque home-page view. Chapter 9 adds our own routing. The admin route alone does not provide a usable account database or staff login; do not try to create a superuser or visit admin as this chapter’s check.

Que. 6 Does the presence of django.contrib.auth in INSTALLED_APPS mean member signup works?

Show answerHide answer

Answer. No. It enables Django’s account support as one project component. We still need a chosen user model, database tables, the relevant pages, and application rules. Those arrive in their planned chapters. A setting is not evidence of a complete user journey.

Two server interfaces, one project

config/wsgi.py and config/asgi.py expose an object named application that a compatible server can call. WSGI means Web Server Gateway Interface; ASGI means Asynchronous Server Gateway Interface. These are agreements about how a Python web application and a server communicate. ASGI also supports asynchronous interactions; we will not choose or configure a production server here.

Both files select config.settings. They are alternative entry points for compatible servers, not two web applications that we must start together. Django’s standard runserver uses the WSGI application setting. Keeping asgi.py does not make that server run under ASGI. Leave both files unchanged; deployment comes much later.

In practice: finding the right file to inspect

Situation. A contributor reports that a requested address is not recognized.

Application. Begin with config/urls.py and the address patterns it includes. For an import/configuration problem, inspect the settings module selected by manage.py instead. The file map narrows the question.

Consideration. A likely starting file is not a diagnosis. Use the actual error and the smallest relevant check before editing anything.

Try it yourself

Write the filename you would inspect for each question: which apps are enabled; where root address matching begins; which command helper selects this project’s settings; and which two files expose the server interfaces. Then rerun the Section 6.2 system check from otahque/ without editing these files.

Que. 7 What should your file map and check show?

Answer. Enabled apps: config/settings.py, in INSTALLED_APPS. Root matching: config/urls.py, selected by ROOT_URLCONF. Command helper: manage.py. Server interfaces: config/wsgi.py and config/asgi.py. The unchanged project should still report System check identified no issues (0 silenced). If an accidental edit causes an error, compare it with the same file in a freshly generated copy (Section 6.5) and correct only the unintended change; keep your own key.
