6.5 Diagnose and check readiness

Raj follows the startup instructions but his browser cannot connect. Reinstalling everything would discard useful clues. We can instead ask which step last worked: finding the files, importing Django, loading the configuration, listening on a port, or making the browser request.

Starting point: the project from 6.2–6.4, with the server stopped. Work in otahque/. No source files change in this section. Your output is a short startup record and a successful repeat of the local page check, with a recovery route for the common failures below.

Diagnose in the order the work happens

If you cannot identify an existing listener, leave it alone. Do not end an unknown process or relax security settings to clear the error. For a controlled alternative, start our project on port 8001 after ensuring your own earlier server is stopped. Choose the block for your shell, still in otahque/. PowerShell:

uv run --no-project --python .venv python manage.py `
  runserver 8001

macOS shell or Linux/WSL Bash:

uv run --no-project --python .venv python manage.py \
  runserver 8001

Visit http://127.0.0.1:8001/ and expect the same Django welcome page. If 8001 is also occupied, do not keep starting processes blindly: inspect your open terminals and choose a known free port. Stop the server you started when the check is complete. The port argument does not change project files or apply database migrations.

Show answerHide answer

Answer. You have not tested the new listener. The request goes to port 8000, which might have no server or a different one. Change the browser address to the exact URL in the new startup message and confirm that this terminal records the request.

Keep a small startup record

From otahque/, with the server stopped, rerun these commands in PowerShell, a macOS shell, or Linux/WSL Bash:

uv run --no-project --python .venv check_environment.py
uv pip check --python .venv
uv run --no-project --python .venv python manage.py check

Record the current directory, Python version, executable path, isolation result, Django version, and system-check result. Then start the server, record its exact address, visit the welcome page, and stop it. These observations make a support question specific. Exclude your secret key and unrelated private paths or data when sharing the record with someone else.

Compare with a fresh copy when needed

If you think a generated file was changed by accident and the error alone does not show what changed, generate a fresh copy of the project and compare that one file. You need this only when something has gone wrong. From Chapter 8, Git will show such changes directly. The commands run startproject in a new, empty sibling folder, so they do not touch your project. If you named your work folder otahque-learning in 6.1, use that name in place of otahque.

PowerShell, starting in otahque/:

cd ..
mkdir otahque-compare
cd otahque-compare
uv run --no-project --python ../otahque/.venv `
  python -m django startproject config .
cd ../otahque

macOS shell or Linux/WSL Bash, starting in otahque/:

cd ..
mkdir otahque-compare
cd otahque-compare
uv run --no-project --python ../otahque/.venv \
  python -m django startproject config .
cd ../otahque

The last command returns you to otahque/. The fresh copy has the same manage.py and five config/ files for this Django version, but no .venv/ of its own. Its SECRET_KEY differs from yours; every other generated line should match. Open the file named in the error in both folders, correct only the unintended change in your own file, and keep your own key. Do not edit the copy, run its server, or copy it over your project. Delete otahque-compare/ when you have finished.

In practice: asking for help with evidence

Situation. Raj reports that the project works in one terminal but not another.

Application. Compare the startup records from both: working directory, interpreter, Django version, check result, and listening URL. The earliest difference is a concrete lead.

Consideration. A successful system check does not prove all future features. From Chapter 9, each new page behaviour also gains an automated test of its result.

Try it yourself

On paper, diagnose this report: “The helper prints Python 3.14.9, an interpreter in this project’s .venv, True, and Django 6.1.2. The system check passes. runserver says the port is already in use.” Name what already works, what failed, and a recovery that preserves another process. Then complete your own startup record using the project you built.

Que. 12 What should the diagnosis and readiness evidence say?

Show answerHide answer

Answer. The selected Python and Django import work, and the configuration check passes. Binding the server to its port failed. Leave an unidentified listener alone; stop your own known earlier server or choose a known free port such as 8001, then visit the matching address. Your record should show the expected environment values, a passing system check, the welcome page and GET / with 200, and the server stopped afterward. No migration or reinstall is needed for a port conflict.

Bringing the chapter together

We moved from an installed framework to a generated project and a response in the browser. The working folder holds the environment and source; config/ collects configuration; manage.py lets us run project-aware commands; and runserver supplies a temporary local listener. We can now explain the starting structure before adding Otahque behaviour.
