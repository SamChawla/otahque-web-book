Checkpoint: Quiz and Challenge

Quiz

Que. 10 Why does every command in this chapter name --python .venv?

Flip to check your answerFold answer back

Answer. So that installation and execution select the same environment, visibly, without relying on activation or on whichever Python a terminal or editor finds first.

Que. 11 What does the final dot in startproject config . mean?

Flip to check your answerFold answer back

Answer. The destination: generate manage.py in the current folder and the config/ package inside it, instead of creating another outer folder.

Que. 12 Which generated file says where root address matching begins, and which setting points to it?

Flip to check your answerFold answer back

Answer. config/urls.py, named by the ROOT_URLCONF setting in config/settings.py.

Que. 13 What does 127.0.0.1:8000 identify?

Flip to check your answerFold answer back

Answer. The loopback address, meaning this computer, and port 8000, the port on which the development server listens by default.

Que. 14 Why do we leave the migration warning unresolved?

Flip to check your answerFold answer back

Answer. Otahque’s custom user model must be chosen in Chapter 17 before the first migration is applied. The development page needs no tables, so applying migrations now would only jump ahead of that decision.

Mini-Challenge

Write a startup record you could send with a help request: the current directory, the four lines from check_environment.py, the uv pip check result, the system-check result, and the exact listening address from runserver. Then remove anything private from it. Do not change any project file.

Que. 15 What should a good record contain, and what should it leave out?

Flip to check your answerFold answer back

Answer. It names the working folder, Python 3.14.9, an interpreter inside this folder’s .venv, True for isolation, Django 6.1.2, a compatible-packages result, a passing check, and http://127.0.0.1:8000/. It leaves out the SECRET_KEY and any personal paths or data that are not needed to diagnose the problem.

What We Learned

  • Installing Django makes a package available to one interpreter; naming --python .venv in every command keeps installation and execution in the same environment.
  • A project collects configuration and apps; otahque/ holds our work, and the config package holds the settings, root URLs, and server interfaces.
  • manage.py selects config.settings and runs Django’s management commands; the system check finds configuration problems but proves no product behaviour.
  • runserver answers on the loopback address for development only; the welcome page is Django’s fallback, not an Otahque page.
  • Migrations stay unapplied until the custom user model is chosen in Chapter 17.
  • Failures are diagnosed by the last step that worked, and recovered without regenerating or deleting work.
