How We Build It

Start from Chapter 23, in the folder containing manage.py, with your own .env (including DJANGO_ADMIN_URL=admin/), the locked environment, 77 passing tests, every migration applied, the Node.js packages from Chapter 14 installed, and Sam’s superuser password from Chapter 18. Step 2 tries a first form in a practice file. Steps 3 and 4 write events/forms.py with its tests first. Step 5 adds the New event page: a view in events/views.py, an address in events/urls.py, the LOGIN_URL setting, the template events/templates/events/form.html, and a link in the navigation. Step 6 saves drafts, with one method added to events/models.py and messages in templates/base.html. Step 7 lets organizers and the administrator open a draft’s page. Step 8 renders the fields with Otahque’s styles, through config/renderers.py, a field template, two widget templates, static/otahque/source.css, and a small script. Step 9 proves the CSRF protection, writes the design note docs/design/event-draft-form.md, and commits. Every test goes in events/tests.py. At the end, 97 tests pass, Sam can save a draft for his New York clinic at 19:00 New York time, and there is no new migration.

The Custom Way

Without Django’s forms, every check, conversion, message, and redisplay is written by hand. This illustration checks two values the way a view would have to, and escapes a typed value before putting it back into the page. Run it with any Python, and do not add it to the project:

illustration_only/by_hand.py (not part of the project)

from html import escape


def check(data):
    errors, cleaned = {}, {}
    title = data.get('title', '').strip()
    if title:
        cleaned['title'] = title
    else:
        errors['title'] = 'This field is required.'
    try:
        cleaned['capacity'] = int(data.get('capacity', ''))
    except ValueError:
        errors['capacity'] = 'Enter a whole number.'
    return errors, cleaned


for posted in ({'title': '', 'capacity': 'forty'},
               {'title': 'Clinic', 'capacity': '50'}):
    errors, cleaned = check(posted)
    for name, value in (errors or cleaned).items():
        print(f'{name}: {value}')
typed = 'Q&A "night"'
print(f'<input name="title" value="{escape(typed)}">')

Output

title: This field is required.
capacity: Enter a whole number.
title: Clinic
capacity: 50
<input name="title" value="Q&amp;A &quot;night&quot;">

It handles two fields. Now count what is missing: there is no HTML for the inputs, no labels, no list of messages beside each field, no check that the request came from Otahque’s own page, and the rules are copies of the model’s, which will drift apart. escape() is there because a typed value written back into a page without it could close the attribute and add HTML of its own; forget it once and the page is open to attack. Django’s forms do each of these jobs, from the model, for every form.

events/forms.py

from zoneinfo import available_timezones

from django import forms

from .models import Event

ZONE_CHOICES = [('', 'Choose a time zone')] + [
    (name, name) for name in sorted(available_timezones())
]


def local_input():
    """A date-and-time box that the browser fills in."""
    return forms.DateTimeInput(
        attrs={'type': 'datetime-local'},
        format='%Y-%m-%dT%H:%M',
    )


class EventForm(forms.ModelForm):
    """Sam's new event. Status is not one of its fields."""

    timezone = forms.ChoiceField(
        choices=ZONE_CHOICES,
        label='Time zone',
        help_text='Starts and Ends are read in this zone.',
    )

    class Meta:
        model = Event
        fields = ['title', 'timezone', 'starts_at',
                  'ends_at', 'location', 'capacity']
        labels = {'starts_at': 'Starts', 'ends_at': 'Ends'}
        help_texts = {
            'location': 'A venue address, or Online.',
        }
        widgets = {'starts_at': local_input(),
                   'ends_at': local_input()}

ZONE_CHOICES is the list for the Time zone field: an empty first choice that asks for a zone, then every zone name Python’s time-zone database knows, sorted. Each choice is a pair, the value sent and the text shown, and here they are the same. local_input() makes the widget for a date and time: type="datetime-local" asks the browser for its own date-and-time picker, and format writes a saved value back in the form that picker reads.

EventForm is a ModelForm. Meta.model names the model, fields is the allowlist, in the order the page shows them, labels and help_texts change what the page says, and widgets chooses the inputs. The field timezone is declared on the class itself, which replaces the one the model would give: the model has a text field for the zone, and the page needs a list. The model’s validator, validate_timezone_name(), still runs when the form calls the model’s validation. Run the tests again:

Step 4: Read the times in the event’s zone

Sam’s form still reads every time in UTC. def in_utc(form, name):
    """A cleaned time from form, shown in UTC."""
    return form.cleaned_data[name].astimezone(UTC)


class EventZoneTests(TestCase):

Add this function after local_input(), with two blank lines before and after it:

events/forms.py (after local_input)

def in_zone(value, zone_name):
    """Read a typed time as a time in the named zone."""
    typed = timezone.make_naive(value)
    zone = ZoneInfo(zone_name)
    first = typed.replace(tzinfo=zone)
    second = typed.replace(tzinfo=zone, fold=1)
    if first.utcoffset() == second.utcoffset():
        return first
    params = {'time': typed.strftime('%H:%M'),
              'zone': zone_name}
    back = first.astimezone(UTC).astimezone(zone)
    if back.replace(tzinfo=None) != typed:
        raise ValidationError(
            '%(time)s does not exist in %(zone)s that '
            'day: the clocks go forward.',
            code='skipped_time', params=params,
        )
    raise ValidationError(
        '%(time)s happens twice in %(zone)s that day: '
        'the clocks go back.',
        code='repeated_time', params=params,
    )

And add this method at the end of the file, inside EventForm, after the Meta class and one blank line below it:

events/forms.py (EventForm, add at the end)

    def clean(self):
        data = super().clean()
        zone = data.get('timezone')
        for name in ('starts_at', 'ends_at'):
            if zone and data.get(name):
                try:
                    data[name] = in_zone(data[name], zone)
                except ValidationError as error:
                    self.add_error(name, error)
        starts = data.get('starts_at')
        ends = data.get('ends_at')
        if starts and ends and ends <= starts:
            self.add_error(
                'ends_at',
                'An event must end after it starts.',
            )
        return data

clean() runs after every field has been cleaned, so data, the cleaned_data that super().clean() returns, holds every value that passed. For each time, in_zone() reads it again in the chosen zone. add_error() attaches a message to a field and removes that field from cleaned_data, which is why the comparison afterwards checks that both times are still there. When the end is not after the start, the message is attached to ends_at, and the model then skips its own constraint for that field, so the message appears once.

Under the Hood: how in_zone() finds a clock change

The field has already turned the text into an aware date and time in the current zone, UTC. timezone.make_naive() takes the zone off again, which gives back exactly what Sam typed, 19:00 on 3 December. replace(tzinfo=zone) then attaches the event’s zone. For an ordinary time that is the answer. Python marks the two readings of a repeated time with fold: 0 for the first, 1 for the second. For an ordinary time both give the same offset from UTC; for a time that happens twice, or not at all, they differ. To tell the two apart, the function converts the first reading to UTC and back: a time that does not exist comes back as a different time, an hour later, while a repeated one comes back unchanged.

The colours were measured against the page’s white, as Chapter 13 measured the others: the error red has a contrast of 6.57 to 1 against white, white text on the success green 6.54 to 1, and the input border 4.60 to 1, against about 1.5 to 1 for daisyUI’s default. WCAG 2.2 asks for 4.5 to 1 for text and 3 to 1 for the edge of a control. The rules sit in @layer utilities because daisyUI 5 styles its fields in that layer, and a rule in an earlier layer would lose to it. A field with an error gets a red border and its message, so colour is never the only sign.

// Choose the browser's time zone when none is chosen yet.
const field = document.getElementById('id_timezone');
const zone = Intl.DateTimeFormat()
  .resolvedOptions().timeZone;

  .some((option) => option.value === zone);
if (known && !field.value) {
  field.value = zone;
}

The last test proves the protection Step 5’s tag relies on. Add one import to events/tests.py, changing from django.test import SimpleTestCase, TestCase to:

Then add at the end of the file:

class CsrfTests(TestCase):
    @classmethod
    def setUpTestData(cls):
        cls.sam = member('sam@example.org', 'add_event')
        cls.url = reverse('events:create')

    def test_a_post_without_the_token_is_refused(self):
        browser = Client(enforce_csrf_checks=True)
        browser.force_login(self.sam)
        refused = browser.post(self.url, NEW_EVENT)
        self.assertEqual(refused.status_code, 403)
        self.assertFalse(Event.objects.exists())
        page = browser.get(self.url)
        token = str(page.context['csrf_token'])
        saved = browser.post(
            self.url,
            NEW_EVENT | {'csrfmiddlewaretoken': token},
        )
        self.assertEqual(saved.status_code, 302)

Client(enforce_csrf_checks=True) makes a test client that checks CSRF tokens, as a real request is checked. It posts without a token and is refused, nothing is saved, and then it fetches the page, takes the token the page was given, and posts again, successfully. page.context holds the variables the page’s template was given, including csrf_token. # New event form: low-level design

Status: Drafted in Chapter 24, for review.
Who: members with events.add_event (Sam, on your
computer). Visitors cannot propose events.

## Request path

- GET /events/new/: login_required, then
  permission_required(add_event, raise 403); an unbound
  EventForm; events/form.html.
- POST /events/new/: the same checks; CsrfViewMiddleware
  refuses a missing or wrong token with 403 first.
  EventForm(request.POST).is_valid():
  - invalid: the same page, status 200, messages beside
    the fields, typed values kept, nothing saved;
  - valid: in one transaction, form.save() (status
    draft, as status is not a field) and
    event.add_organizer(user); message "Draft saved.";
    302 to the event page (Post/Redirect/Get).
- GET /events/<id>/: Event.is_visible_to(user):
  published for all; otherwise holders of view_event
  and current organizers; 404 for everyone else.

## Validation layers

1. Fields: required values, lengths, whole numbers,
   the zone from the list.
2. EventForm.clean(): starts and ends read in the
   event's zone (in_zone); times a clock change skips
   or repeats refused; ends after starts, on Ends.
3. Model full_clean(): validate_timezone_name and
   Chapter 21's constraints (capacity more than 0).
4. Database: Chapter 21's constraints refuse a bad
   row from anywhere.

## Limits and later work

- Sign-in is the admin's page until Chapter 27, so
  only staff can sign in through a browser.
- The edit form must show stored times in the event's
  zone (Chapter 25); publishing is Chapter 26.
- Once Chapter 28 activates each viewer's zone, clean
  the times under the event's zone instead.
- Widget templates copy Django 6.1's; check them when
  Django is upgraded.
