Checkpoint: Quiz and Challenge

Quiz

Que. 2 What is the difference between form.data['capacity'] and form.cleaned_data['capacity'] for Sam’s clinic, and when can you read the second?

Flip to check your answerFold answer back

Answer. data holds the text the browser sent, '50'; cleaned_data holds the checked, converted value, the number 50. cleaned_data exists only after is_valid() has run, and holds only the values that passed.

Que. 3 Why does the view redirect after saving, instead of rendering the event’s page directly?

Flip to check your answerFold answer back

Answer. So the last request is a GET. Refreshing or going back after a redirect asks for the event’s page again; refreshing a page rendered by the POST would send the form again and save a second event.

Que. 4 Sam’s browser sends status=published with an otherwise valid event. What is saved, and which line of code decides that?

Flip to check your answerFold answer back

Answer. A draft. status is not in EventForm.Meta.fields, the allowlist, so the posted value is ignored and the model’s default, draft, is saved.

Que. 5 A capacity of 0 is refused, and the message appears at the top of the form rather than under Capacity. Which layer refused it, and why there?

Flip to check your answerFold answer back

Answer. The model, through full_clean(), which is_valid() calls for a ModelForm: the rule is Chapter 21’s constraint, and the model reports constraint messages for the whole form. The form’s field allows 0, because the model’s field is a PositiveIntegerField.

Que. 6 Every POST test in Steps 3 to 8 passes without a CSRF token. Why, and how does Step 9 prove the protection anyway?

Flip to check your answerFold answer back

Answer. Django’s test client skips the CSRF check by default. Step 9’s test creates its client with enforce_csrf_checks=True, so a POST without the token is refused with 403, and one with the page’s token is accepted.

Mini-Challenge

Que. 7 The community plans online calls at 01:30 on three days: in London on 28 March 2027 and on 31 October 2027, and in Kolkata on 28 March 2027. London’s clocks go forward at 01:00 on the first day and back at 02:00 on the second; Kolkata’s never change. Predict which of the three Sam’s form accepts, and why each refusal happens. Then check your prediction with a practice file that only validates, so nothing is saved.

Flip to check your answerFold answer back

Answer. London on 28 March is refused as a skipped time, because 01:00 to 01:59 does not exist that day. London on 31 October is refused as a repeated time, because 01:00 to 01:59 happens twice. Kolkata is accepted. One file that checks it, run with uv run python ../practice/challenge.py:

../practice/challenge.py

import setup_django
from events.forms import EventForm

BASE = {'title': 'Planning call', 'location': 'Online',
        'capacity': '12'}
CASES = [('Europe/London', '2027-03-28'),
         ('Europe/London', '2027-10-31'),
         ('Asia/Kolkata', '2027-03-28')]
for zone, day in CASES:
    form = EventForm(BASE | {
        'timezone': zone,
        'starts_at': f'{day}T01:30',
        'ends_at': f'{day}T03:30',
    })
    errors = form.errors.as_data().get('starts_at')
    result = errors[0].code if errors else 'accepted'
    print(zone, day, result)

Output

Europe/London 2027-03-28 skipped_time
Europe/London 2027-10-31 repeated_time
Asia/Kolkata 2027-03-28 accepted

errors.as_data() gives the ValidationError objects behind the messages, and code is the short name in_zone() gave each one. The file calls no save(), so your rows are unchanged. The same typed text is fine in one zone and impossible in another, which is why the form reads it in the event’s zone.

What We Learned

  • A form sends values as text with POST; the view answers a GET with an empty form and a POST with errors or a redirect.
  • A Django form checks, converts, and explains; cleaned_data holds the values code may trust, only after is_valid().
  • A ModelForm takes its fields and rules from the model, and its fields list is an allowlist: what is not named cannot be set.
  • Rules live in four layers: fields, the form’s clean(), the model, and the database, and each rule lives as low as it can.
  • Typed times mean what the event’s zone says; times that a clock change skips or repeats are refused, not guessed.
  • login_required, permission_required, and a model method decide who may create events and who may see a draft.
  • Post/Redirect/Get and a message keep a refresh from saving twice and tell the person what happened.
  • CSRF tokens stop forged posts; only a test client with enforce_csrf_checks=True proves it.
  • A form renderer and templates put Otahque’s classes on fields while keeping labels, help, errors, and aria- attributes connected.
